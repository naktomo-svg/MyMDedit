# MyMDedit 仕様書

最終更新: 2026-10-29。v0.1.0(コミット `b6a4037`)の実装から起こした、現状の機能仕様書。移植元のMyWinApp(WinUI 3版。非公開・開発終了)と意図して変えた点は`README.md`の「移植元(MyWinApp)との違い」にまとめてある。

## 1. 概要

MyMDeditは、Windows向けのシンプルなMarkdownエディタ。ウィンドウ左側でMarkdownを編集すると、右側にHTMLプレビューがリアルタイムに表示される、左右分割の単一ウィンドウ構成。Win32 API(`windows`クレート)とWebView2で作ったネイティブアプリで、単一の`MyMDedit.exe`だけで動く。

## 2. 動作環境・技術スタック

- Windows 10 / 11 の x64 版。要件は README に「Windows 10 バージョン1809以降」と書いているだけで、実行時にバージョンは確認しない。マニフェストの`supportedOS`は Windows 10/11 の GUID のみ。
- 必要なランタイムは[WebView2ランタイム](https://developer.microsoft.com/microsoft-edge/webview2/)だけ。.NET・VC++ランタイム(Cランタイムは静的リンク)・MSIXのインストールは要らない。WebView2ランタイムがない場合も起動は止めず、プレビューなしで編集できる(4.2参照)。
- 言語は Rust(edition 2024)。主要クレート:
  - `comrak` 0.56(Markdown→HTML。`default-features = false`)
  - `webview2-com` 0.39(WebView2 の COM バインディング。WebView2 SDK のローダーは静的リンクされ、`WebView2Loader.dll`は要らない)
  - `windows` 0.62(webview2-com が使う 0.62 系と同じマイナーバージョンに揃える必要がある。揃っていないと、webview2-com が返す COM インターフェースの型と、こちらが名前で参照する型が別物になる)
  - `serde` / `serde_json`(設定ファイル)、ビルド時のみ`embed-resource`(アイコン・マニフェスト・バージョン情報の埋め込み)
- exe のバージョン情報(VERSIONINFO)は`build.rs`が`Cargo.toml`のバージョンから生成する。バージョン番号を書くのは`Cargo.toml`の1か所だけ。
- リリースビルドは`lto = true`・`codegen-units = 1`・`strip = true`で、コンソールウィンドウを持たない(デバッグビルドはコンソールあり)。

## 3. 画面構成

単一ウィンドウ(`WS_OVERLAPPEDWINDOW`)。タイトルバーと枠は OS 標準のもので、ダークテーマのときだけ DWM でタイトルバーを暗くする(4.20)。メニューバーはウィンドウの標準メニューで、その下のクライアント領域を上から次の順に分ける。

1. **Markdown記法ツールバー**(高さ40DIP): メニューバーの下に独立した行として置く。左端に縦の区切り線を描き、その右に記法ボタン8個(4.7)を並べる。行の下端に1pxの境界線を引く。
2. **エラー通知バー**: 通知があるときだけ現れ、ツールバーの直下を占めて本体を押し下げる。通知がないときの高さは0(4.19)。
3. **本体**: 左にエディタ(RichEdit)、中央に1pxの区切り線、右にプレビュー(WebView2)。区切り線の1pxを除いた幅を**常に左右等分**する。区切り線はドラッグできない。エディタは本文を四辺から16DIP内側に描く。WebView2 ができるまで(できなかった場合も)、プレビューの領域はエディタと同じ背景色で塗っておく。
4. **フッター**(高さ28DIP): 上端に1pxの境界線を引き、行数・文字数・ズーム倍率を表示する(4.5)。

- 起動時のウィンドウは 1200×800DIP で、プライマリ画面の中央に置く。位置と大きさは保存しない。最小サイズは 640×400DIP。
- 起動直後と、メインウィンドウがフォーカスを受け取ったときは、キーボードフォーカスをエディタに置く。

## 4. 機能仕様

### 4.1 エディタ

- 左ペインは RichEdit(`RICHEDIT50W`)を**プレーンテキストモード**(`TM_PLAINTEXT | TM_MULTILEVELUNDO`)で使う。古典的な EDIT コントロールではなく RichEdit を選んだのは、多段の元に戻す/やり直し、32K文字の上限がないこと、ネイティブのズームの3点のため。`EM_SETTEXTMODE`はコントロールが空のうちでないと効かないため、生成した直後に送る。
- 文字数の上限は`EM_EXLIMITTEXT`で`0x7FFFFFFE`まで引き上げる(RichEdit の既定は32K文字)。
- 行はウィンドウ幅で折り返す(横スクロールなし)。`ES_NOHIDESEL`により、フォーカスが外れても選択範囲は見えたまま残る(検索ダイアログを操作している間もヒット箇所が見える)。
- **改行は単独の`\r`で保持する**。移植元の WinUI `TextBox`と同じ表現なので、ツールバーの処理を書き換えずに移植できた。選択位置はすべて、この本文に対する UTF-16 コード単位のオフセットで扱う。ツールバーやリスト継続が書き込む改行も常に`\r`。保存時に文書の改行コードへ書き戻す(4.12)。
- RichEdit は最後の段落記号の分だけ本文の末尾より先の位置を返すことがある。その値で本文を切り出すとウィンドウプロシージャ内で panic してプロセスが落ちるため、選択範囲は必ず本文の長さに収めてから使う。
- **元に戻すの粒度**: ツールバー・メニューの記法操作、Enter によるリスト継続、Tab/Shift+Tab、タスクの切り替え、すべて置換は、どれも「1つの範囲を1つの文字列で置き換え、そのあと選択を設定する」1回の編集として`EM_REPLACESEL`(元に戻せる指定)で適用する。そのため**1操作がちょうど1回の元に戻すに対応する**。
- ファイルの読み込み(`EM_SETTEXTEX`)は元に戻す履歴を消す。読み込み自体は元に戻せない。読み込み後のキャレットは先頭。
- フォントは設定の`editor_font_family`(カンマ区切りの候補)のうち、インストールされている最初のものを使い、どれもなければ`Consolas`。フォント名は RichEdit の上限に合わせて31 UTF-16単位で切る。サイズは設定値(px)を twips に換算する。文字色と背景色はテーマのパレットから取る。
- 元に戻す/やり直し/切り取り/コピー/貼り付け/すべて選択は、`EM_UNDO`/`EM_REDO`/`WM_CUT`/`WM_COPY`/`WM_PASTE`/`EM_SETSEL(0,-1)`をエディタに送るだけ。
- アプリ自身が本文や書式を変えるとき(読み込み、新規、フォントの適用)は`suppress_dirty`を立て、`EN_CHANGE`で未保存フラグが立たないようにする(`EM_SETTEXTEX`も`EM_SETCHARFORMAT`も`EN_CHANGE`を出しうる)。

### 4.2 プレビューの描画

- **再描画のきっかけ**: エディタの`EN_CHANGE`で描画要求のメッセージをポストする。要求が既にキューにある間は重ねてポストしないので、たまっている編集を処理し終えてから1回描画する。時間で待つデバウンスではない。打鍵が描画より遅ければ遅延は生じず、貼り付けやキーリピートのような連続入力だけがまとまる。ポストに失敗したときはその場で描画する。
- 表示に関わる設定が変わったとき(4.15)と、テーマが「システムの既定」で OS のライト/ダークが切り替わったときも再描画する。
- **Markdown 変換**: comrak で次の拡張を有効にする。
  - GFM の取り消し線・表・自動リンク・タスクリスト
  - 上付き・下付き・脚注・定義リスト
  - 見出しの id(接頭辞なし)
  - **CJK に配慮した強調**(`cjk_friendly_emphasis`): 日本語では必須。CommonMark は`**`の前後の文字で強調の開閉を決めるが、日本語には単語間の空白がなく、`、。「」():`はすべて約物なので、これがないと`**注意:**内容`や`これは**「太字」**です`がアスタリスクのまま表示される。GitHub が太字にしない箇所までプレビューでは太字になることは承知のうえで受け入れている。
  - 生HTMLの出力(`render.unsafe = true`。4.3)
- **HTML文書の組み立て**: 描画のたびに`<!DOCTYPE html>`・`<meta charset="utf-8">`・CSP の`<meta>`・`<style>`(設定から作るCSS)・`<body>`(変換結果)を1回で連結する。テンプレートへの置換にしないのは、置換済みの部分を再び走査してしまい、設定値に目印の文字列が入っていると本文が重複しうるため。
- **設定から作るCSS**:
  - 基本(ライト)の配色にテーマの配色を足し、続けてフォント・背景色・表のスタイルを足す。
  - `body`のフォント: フォント名をカンマで分け、`serif`・`sans-serif`・`monospace`・`cursive`・`fantasy`・`system-ui`以外は`"…"`で囲んで`\`と`"`をエスケープする。`<`・`>`・制御文字を含む候補は捨てる。結果は`<style>`要素の中に入り、HTML のトークナイザーは CSS の引用符と関係なく`</style`で要素を閉じるうえ、CSS の文字列は改行で終わってその後ろの`}`が規則を閉じてしまうため。
  - 背景色: `#RGB`/`#RRGGBB`の形の値だけを`body { background: <色> !important; }`として出力する。settings.json はアプリの外から書き換えられ、値はCSSにそのまま入るので、`#fff; } body {display:none} x {`のような値で規則を抜け出せてしまうため。読み込み時にも検証する(5章)。
  - 表のヘッダーを灰色にする設定と縞模様の設定。両方オンのときは、縞をヘッダーと接しないよう偶数行から塗る。
- **既定の配色**:
  - ライト: 本文`'Segoe UI', sans-serif` 15px・行の高さ1.6・文字`#1a1a1a`・背景`#ffffff`。`code`/`pre`は Consolas 系で半透明の灰色の背景、`pre`は横スクロール。引用は左に4pxの線。リンク`#0067c0`。`img { max-width: 100% }`。
  - ダーク: 文字`#e6e6e6`・背景`#1e1e1e`・`code`/`pre`の背景`#2b2b2b`・リンク`#6cb6ff`。
  - テーマが「システムの既定」のときは、ダークの配色を`@media (prefers-color-scheme: dark)`で囲んで足し、判定を WebView に任せる。
- **プレビューへの反映**: `NavigateToString`で読み込む(`preview::navigate`が唯一の呼び出し元)。WebView2 側から見るとページの URI は`data:text/html;charset=utf-8;base64,…`になる。
- **大きさの上限**: `NavigateToString`は約2MBを超える文字列を拒否する(対象は CSS を含む HTML 全体)。失敗したときは「プレビューを更新できませんでした。文書が大きすぎる可能性があります（プレビューの上限は約2MBです）。編集内容は保持されています。」をエラー通知に出す。打鍵のたびに失敗するので、通知は失敗が続く間に1回だけで、更新に成功すると数え直す。文書を切り詰めて表示し直すことはしない。
- 最新の描画の読み込みが失敗したときは「プレビューを表示できませんでした。(<状態コード>) 編集は引き続き行えます。」を出す(成功するまで1回だけ)。より新しい描画に追い越されたものや、ガードが取り消したものは日常的に起きるので、記録だけにする。
- **WebView2 の初期化**: 起動時、ウィンドウを表示する前に始める。環境・コントローラーの作成と設定は非同期のコールバックで進み、どの段階で失敗しても「プレビューを初期化できませんでした。WebView2 ランタイムがインストールされているか確認してください。編集は引き続き行えます。」を出す。必須のイベント(4.3)を持たない古いランタイムも同じ扱いになる。
- ユーザーデータフォルダは`%LOCALAPPDATA%\MyMDedit\WebView2`(`LOCALAPPDATA`がなければ`%TEMP%\MyMDedit-WebView2`)。

### 4.3 プレビューの安全対策

Markdown に直接書いた HTML は**サニタイズせず、そのまま描画する**。第三者が書いた`.md`を開く経路が実際にあるので、実行と外部への通信を次の3層で封じる。① CSP、② `IsScriptEnabled = false`、③ `preview.rs`のイベントハンドラー。③のうち**通信を実際に止めるのは`WebResourceRequested`のリクエストフィルターだけ**で、`NavigationStarting`のガードが止めるのはページの切り替えにすぎない(取り消した時点でリクエストは送られている。`<meta refresh>`による http:// への遷移で、ガードが遮断を記録しているのにリクエストは届いていたことを確認した)。

- **取得・接続のための要素は文字として表示する**: `base`・`embed`・`fencedframe`・`frame`・`frameset`・`iframe`・`link`・`meta`・`object`・`portal`の開始タグと終了タグは、先頭の`<`を`&lt;`にして要素として扱わない。これらはプレビュー上では取得か接続をする以外に働きがなく、しかも実行時の防御層が見るのはリクエストだけなのに、リクエストなしでも動くため(`<link rel=dns-prefetch/preconnect>`は任意のホストの名前解決と接続をし、`<iframe src>`はフレームの遷移を取り消すより先に接続を開く)。
  - タグ名の判定は大文字小文字を区別せず、タグ名の直後が空白類・`/`・`>`・文書の終わりのときだけ一致とみなす(HTML のトークナイザーがタグ名を終える文字と同じ)。`<linkx>`のような別の要素は対象外。
  - 変換後の本文全体にかけても安全。comrak は Markdown の本文に現れる`<`をすべてエスケープするので、`<tag`が残っているのは生HTMLの部分だけ。アプリ自身の CSP の`<meta>`は対象外。
  - `<details>`・`<img>`・`<a href>`などはそのまま残る。
- **CSP**: `default-src 'none'; img-src data: https:; style-src 'unsafe-inline'; base-uri 'none'; form-action 'none'`
  - 外部のスタイルシート・フォント・フレームとスクリプトを止める。`base-uri`と`form-action`は`default-src`に従わないので明示する。
  - 画像は`https:`と`data:`だけを許す。ツールバーの画像挿入で外部の URL を使えるようにするため。平文の`http:`の画像は表示しない。
  - CSP はトップレベルのナビゲーションを制御しない。それはナビゲーションガードの役目。
- **WebView2 の設定**: `IsScriptEnabled`・`IsZoomControlEnabled`・`IsStatusBarEnabled`・`AreDevToolsEnabled`・`IsWebMessageEnabled`・`AreHostObjectsAllowed`をすべて false にする。DevTools が有効なままだと、F12 や「検証」で文書に対するコンソールが開き、スクリプトなしの前提が崩れる。対応するランタイムでは自動入力とパスワードの保存も切る。ズームとスクロールに使う`ExecuteScript`は`IsScriptEnabled`の影響を受けない(公式に明記されている)。既定のコンテキストメニューは無効にしていない。
- **リクエストフィルター(`WebResourceRequested`)**: すべての URI・コンテキスト・リクエスト元(対応ランタイムでは文書以外のリクエスト元も)に登録する。URI がガードと同じ拒否リストのスキームで始まるものは、**画像の`https:`を除いて**、外へ送らずにローカルで`403 Blocked`を返す。アプリ自身の文書は`data:`なので当たらない。URI やコンテキストを取得できなかったときは遮断する。
- **ナビゲーションガード(`NavigationStarting`)**: 次の2条件が**両方とも**成り立つ遷移だけを通す。
  - **アプリ自身の遷移であること**: `NavigateToString`の直前に1増やし、ガードが通したときに1減らす「実行中の自前ナビゲーション数」が正であること。bool ではなく数にしているのは、打鍵ごとに描画すると自前のナビゲーションが同時に2つ進行しうるため。
  - **拒否リストのスキームでないこと**: `http:`・`https:`・`file:`・`ftp:`・`ws:`・`wss:`(大文字小文字を区別しない)。`NavigateToString`が生成しえないスキームなので、文書が仕掛けた遷移でしかありえない。カウンタが正のままメッセージループを1周する隙と、カウンタが戻り損ねた場合の両方に対する2段目の防御。比較はバイト単位で行う(`&str`を途中で切ると多バイト文字で panic し、コールバック内の panic はプロセスを落とすため)。
  - 2条件は拒否する方向にしか働かない。**URI の形にもとづく許可リストにしてはならない**: `NavigateToString`の URI は`about:blank`ではなく`data:text/html;…`で、移植元では推測を外した許可リストがすべての描画を取り消し、プレビューが真っ白になった。**`IsUserInitiated`を条件に加えてもならない**: WebView2 は API から始めたナビゲーション(`NavigateToString`を含む)を「ユーザーが始めたもの」と文書化している。
  - 判定は`Result`を返す関数で計算し、`Err`は取り消しとして扱う。WebView2 はハンドラーが返したエラーを無視して既定の動作(遷移)を続けるので、途中で`?`で抜けると通す側に倒れてしまうため。
- **ガードを通らない経路は個別に取り消す**:
  - `FrameNavigationStarting`: フレーム内の遷移は`NavigationStarting`に届かない。このアプリが描くものにフレームは要らないので、すべて取り消す。
  - `DownloadStarting`: `<a href="data:…" download>`は`NavigationStarting`を経ずにダウンロードを始め、ランタイムが警告しない種類のファイルなら確認なしにダウンロードフォルダへ保存される。すべて取り消す。このイベントを持たないランタイムではプレビューを一切表示しない。
  - `ClientCertificateRequested`: 外へ出られる唯一のリクエストである https 画像のサーバーはクライアント証明書を要求でき、何もしないと証明書の選択画面が出て、選んだ証明書(社用のものなら持ち主の名前入り)が文書の作者に渡る。常に取り消す。必須である点は`DownloadStarting`と同じ。
  - `NewWindowRequested`: Ctrl/Shift/中ボタンでのクリック、`target="_blank"`、コンテキストメニューの「新しいウィンドウで開く」は`NavigationStarting`を通らず、開くポップアップには`IsScriptEnabled = false`も CSP も引き継がれない。ポップアップを一切作らせない。
  - `LaunchingExternalUriScheme`(対応ランタイムのみ): `mailto:`や`ms-settings:`などの OS のプロトコル起動を取り消す。
- **判定を実行できなかったとき**(取り消しの設定そのものの失敗): プレビューを止める。以後は文書を読み込まず、コントローラーを非表示にして、「プレビューの安全確認に失敗したため、プレビューを停止しました。編集と保存は引き続き行えます。」を出す。
- **`ready`による制御**: すべてのハンドラーと設定を入れ終えた最後に`ready`を立て、それまでは文書を読み込まない。設定が途中までの WebView に敵対的な文書を読み込ませないため。
- **InPrivate プロファイル**: コントローラーは InPrivate で作り、履歴・ダウンロード・キャッシュはメモリにだけ置く。ページは文書全体を収めた`data:` URI で、通常のプロファイルでは取り消したダウンロードのたびにその URI を持つ履歴の行がディスクに残り、文書を消した後も内容が読めたため。InPrivate のオプションを持たない古いランタイムでは、そのことを記録して通常のプロファイルで作る。
- **`ProcessFailed`**: レンダラーまたはブラウザープロセスの終了を受けたら、コールバックから戻った後で回復する(回復処理はイベントを出しているコントローラーを閉じるため)。まず自前ナビゲーション数を0に戻す(死んだプロセスは自分のナビゲーションを報告しないため)。
  - レンダラー: 3回までその場で描画し直す。それを超えると「この文書を表示するとプレビューの処理が停止するため、自動での再表示をやめました。…」を出し、次の編集のときに再び試みる。描画に成功すると回数は0に戻る。
  - ブラウザー: セッション中3回まで作り直す。それを超えると「プレビューの処理が繰り返し停止したため、再起動をやめました。…」を出す。
  - GPU やユーティリティプロセスの終了などは記録だけにする。
- **遮断の記録**: 遮断したものはどれも種類ごとの名前(`PreviewNavigationBlocked`・`PreviewRequestBlocked`・`PreviewDownloadBlocked`など)で記録する。URI は先頭200文字まで。遮断はエラー通知には出さない。
- **リンクのクリック**: プレビュー内のリンクをクリックしても何も起きない(ブラウザーで開く機能はない)。
- **承知のうえで受け入れているリスク**:
  - https の画像は取得するので、文書を開いたことが画像の置き場所のサーバーに伝わる。Cookie や認証情報は送られないので、伝わるのはその事実だけ。
  - リンクをクリックすると、遮断されるリクエストより前に TCP/TLS 接続が張られる。ユーザーのクリックが要るので受け入れている。
- 以上は`tests/security/`のペイロードと`run-all.ps1`で回帰テストする。

### 4.4 スクロール同期とズーム

**スクロール同期**

- **エディタからプレビューへの一方向**。プレビューをスクロールしてもエディタは動かない。
- エディタの位置は50msごとのタイマーで読み、割合が前回から変わったときだけ同期する。割合は`GetScrollInfo(SB_VERT)`から`(nPos − nMin) ÷ (nMax − nMin + 1 − nPage)`で求め、0〜1に収める。`EM_GETSCROLLPOS`を使わないのは、16ビットに制限されていて、長い文書では約65535ピクセルより先で追従しなくなったため。
- プレビューには`ExecuteScript`で`scrollTop = (scrollHeight − clientHeight) × 割合`を設定する。割合で合わせるので、画像・コードブロック・表など高さの対応が両側でそろわない箇所ではずれる。先頭と末尾は一致する。
- 描画のたびにプレビューは作り直されて先頭に戻るので、読み込みが完了するたびに当て直す。ズームを変えたときも当て直す。
- ズームとスクロールは1つのスクリプトにまとめ、**ズーム → スクロール**の順で実行する(ズームは文書の高さを変えるため、構造で順序を固定している)。
- スクリプトの実行中に来た要求は最新の値だけを覚えておき、完了したら1回だけ流し直す(タイマーで間引くのではなく、WebView の処理速度に合わせる方式)。失敗は記録だけにする。

**ズーム**

- エディタとプレビューの表示倍率を、**50%〜200%の範囲で10%刻み**に連動して変える。既定は100%。**セッション中だけ有効**で、設定には保存せず、起動するたびに100%から始まる。
- エディタは`EM_SETZOOM`、プレビューは CSS の`document.body.style.zoom`で倍率を掛ける。
- 操作方法:
  - **Ctrl+マウスホイール**: **エディタ上でだけ**働く。RichEdit 独自の「エディタだけのズーム」を横取りし、アプリ全体のズームに置き換えている。回転量120(1ノッチ)ごとに1段とし、1ノッチ未満の端数はためておく(高精度タッチパッドが小さな値を大量に送ってきて、その1つ1つで10%ずつ動いていたため)。回転方向が逆になったら端数は捨てる。
  - **Ctrl+"+"**: テンキーの`+`、メインキーの`+`、Ctrl+Shift+メインキーの`+`の3通り。日本語配列などではメインキーの`+`に Shift が要り、アクセラレータの修飾キーは完全一致で照合されるため。
  - **Ctrl+"-"**: テンキーとメインキーの`-`。
  - **Ctrl+0**: メインキーとテンキーの`0`。100%に戻す。
- プレビュー上の Ctrl+マウスホイールでは何も起きない(WebView2 のネイティブズームを切っているため)。メニューにズームの項目はない。

### 4.5 フッター

左から次の3項目を表示する。対象は常に文書全体で、値はプレビューの再描画と同じタイミングで計算し直す。

- **`行: N`**: 改行の数 + 1。`\r\n`は1つの改行、`\r`と`\n`も単独で1つと数える。空の文書は1行で、末尾の改行の後ろにも1行あると数える(`a⏎b⏎`は3行)。
- **`文字: N`**: UTF-16 コード単位数。改行も1つと数え、サロゲートペアの文字は2と数える。
- **`ズーム: N%`**: 4.4のズーム倍率。

行数と文字数は3桁ごとにカンマで区切る。

### 4.6 メニューバー

メニューは「ファイル」「編集」「検索」「設定」の4つ。項目の右側のショートカットは表示用の文字列で、実際のキーはアクセラレータ一覧(7章)と RichEdit の標準動作で決まる。

#### ファイル
- **新規**(Ctrl+N): 破棄確認(4.18)を通ってから、ファイルパスと文書形式を捨て、起動時と同じサンプル文書に戻す。ファイル名は「無題.md」に戻る。
- **開く**(Ctrl+O): 先に破棄確認を行い、それから OS 標準のファイル選択ダイアログを開く(4.12)。順序を逆にすると、確認から実行した保存のあとに、保存前に選んだ内容を読み込むことになりかねないため。
- **保存**(Ctrl+S): 無題のときは「名前を付けて保存」になる。外部での変更の確認(4.13)を経て書き込む。
- **名前を付けて保存**(Ctrl+Shift+S): OS 標準の保存ダイアログを開く(4.12)。
- **最近使ったフォルダ**(区切り線の下、最大3件): 4.14。
- **終了**: 破棄確認を通ってからウィンドウを閉じる。

#### 編集

- **タスクの切り替え**(Ctrl+Enter): 4.8。

#### 検索

### 4.7 Markdown記法ツールバー

メニューバーの下の行に、オーナー描画のボタンを左から次の順に並べる。アイコンは Segoe Fluent Icons(なければ Segoe MDL2 Assets)。ツールチップの文字列はボタンのウィンドウテキストにも設定しているので、スクリーンリーダーや UI オートメーションからはこれがボタンの名前として見える。

| ボタン | ツールチップ(= アクセシブル名) |
|---|---|
| 太字 | 太字 (\*\*太字\*\*) |
| 斜体 | 斜体 (\*斜体\*) |
| 見出し(「H」+▼) | 見出し |
| 箇条書き | 箇条書きリスト (- 項目) |
| 番号付き(「1.」) | 番号付きリスト (1. 項目) |
| リンク | リンク ([テキスト](URL)) |
| コード | コード (\`code\`) |
| その他(「その他」+▼) | その他の記法 |

- 「見出し」と「その他」はボタンの左下からポップアップメニューを開く。Win32 のメニュー項目にはツールチップがないので、挿入される記法は項目の右側の列に表示する。
  - 見出し: 見出し1〜見出し3
  - その他: 引用・水平線・画像・テーブル・取り消し線・コードブロック・タスクリスト
- 記法を挿入したあとは、フォーカスをエディタに戻す。どの操作も元に戻す1回分(4.1)。
- オーナー描画のボタンを素早く2回押すと、2回目が`BN_DOUBLECLICKED`として届く。これもクリックとして扱う。

以下、`⏎`は改行(エディタ内部では`\r`)、`|`はキャレット、`[…]`は操作後に選択される範囲を表す。

- **囲み系**(太字`**`・斜体`*`・取り消し線`~~`・インラインコード`` ` ``):
  - 選択あり: 選択範囲を記法で囲み、元の文字列部分を選択したままにする。`a[b]c` → `a**[b]**c`
  - 選択なし: プレースホルダー入りの記法を挿入し、プレースホルダーを選択する(そのまま入力すれば上書きできる)。プレースホルダーは`太字`/`斜体`/`取り消し線`/`コード`。
  - 複数行の選択も、行ごとではなく選択全体を1組の記法で囲む。
- **リンク・画像**: `[ラベル](url)` / `![ラベル](url)`を挿入する。ラベルは選択した文字列、なければ`リンクテキスト`/`代替テキスト`。挿入後は**常に`url`の部分を選択する**(コピー済みの URL をそのまま貼り付けられるように)。画像がプレビューに出るのは`https:`と`data:`だけ(4.3)。
- **コードブロック**: 選択範囲(なければ`コード`)を`` ``` ``の行で挟み、中身を選択する。言語名は付けない。フェンスが独立した行になるよう、隣の文字が改行でなければ前後に改行を1つ足す(文書の先頭・末尾では足さない)。
- **見出し(H1〜H3)**: 選択開始位置の1行だけが対象。行頭(1桁目)に見出し記法(`#`〜`######`の直後に半角スペース)があれば、それを取り除いてから新しいレベルの記法を付ける(積み重ならない)。`## 見出し` → H1 → `# 見出し`。操作後はキャレットを新しい記法の直後に置く。字下げした見出しや`#見出し`(スペースなし)は既存の記法とみなさない。
- **行頭付与系**(箇条書き`- `・番号付き`N. `・引用`> `):
  - 選択なし: キャレットの行の行頭に記法を付け、キャレットを記法の文字数だけ後ろへずらす。
  - 選択あり: 選択が及ぶすべての行に付け、書き換えたブロックの末尾にキャレットを置く。選択の終端がちょうど次の行の先頭にある場合(行末の改行まで含めて選んだ場合)、その行は含めない。
  - 番号付きは対象行に上から`1. `、`2. `…を振る。空行も対象に数える。
  - 既存の記法は取り除かない(`- a`に箇条書きを押すと`- - a`)。
- **ブロック挿入系**(水平線`---`・テーブル): 選択範囲(なければキャレット位置)をブロックで置き換える。表や水平線として描画されるには前後に空行が要るので、隣の文字が改行なら改行を1つ、改行でなければ2つ足す(文書の先頭・末尾では足さない)。挿入後はブロック全体を選択する。テーブルは`| 見出し1 | 見出し2 |⏎| --- | --- |⏎| セル1 | セル2 |`。
- **タスクリスト**: 4.8の「タスクの切り替え」と同じ処理。

### 4.8 リストの自動継続・字下げ・タスクの切り替え

**リスト行**とは、行頭の半角スペースによる字下げ(0個以上)に続けて、タスク`- [ ] `/`- [x] `/`- [X] `、箇条書き`- `、番号付き`N. `(N は ASCII 数字)のいずれかがある行。`*`・`+`・`N)`の形やタブによる字下げはリスト行とみなさない。

**自動継続(Enter)**

- キャレットが記法より後ろにあれば、「改行 + 同じ字下げ + 次の記法」を挿入し、キャレットを新しい行の記法の直後に置く。
  - 番号付きは番号に1を足す(`9. a|` → `9. a⏎10. |`)。後に続く行の番号は振り直さない。
  - タスクの次の行は常に未チェック(`- [x] a|` → `- [x] a⏎- [ ] |`)。
  - キャレットが本文の途中なら、そこで行を分け、後半が新しい項目になる。
- **リストからの脱出**: 記法だけで本文のない行(`- `、`3. `、`    - `など)で Enter を押すと、行全体(字下げを含む)を消して改行を1つ入れる。1段浅くするのではなく、リストを完全に抜ける。
- 次のときは通常の Enter のまま: 選択範囲がある、キャレットが字下げか記法の中にある、リスト行でない、Ctrl または Alt と一緒に押した。Shift+Enter は Enter と同じく継続する。
- RichEdit は Enter の改行を`WM_CHAR`ではなく`WM_KEYDOWN`の時点で入れるので、`WM_KEYDOWN`の`VK_RETURN`で処理し、`TranslateMessage`が既に積んだ`'\r'`の`WM_CHAR`を1つ捨てる。IME の変換を確定する Enter は`VK_PROCESSKEY`として届くので介入しない。

**字下げ(Tab / Shift+Tab)**

- 選択が及ぶ行(なければキャレットの行)が**すべて**リスト行のときだけ働く。1行でもリスト行でない行があれば、Tab は通常どおりタブ文字を入れる。
- Tab は各行の行頭に**半角スペース4つ**を足す。`- `と`N. `のどちらの下にも入れ子にでき、しかもインデントによるコードブロック扱いにならない幅だから。Shift+Tab は先頭の空白を最大4つ取り除く。
- 選択があるときは、操作後に書き換えた行全体を選択する。キャレットだけのときは、キャレットが文字列と一緒に動く。
- 字下げのない行で Shift+Tab を押しても本文は変わらない。このときは空の元に戻す段を作らないよう置換を行わない。
- Ctrl/Alt を伴う Tab には介入しない。

**タスクの切り替え(Ctrl+Enter / 編集メニュー / その他→タスクリスト)**

選択が及ぶすべての行(なければキャレットの行)を、字下げを残して次のように書き換える。複数行を選択しているときは空行に手を付けない。

| 操作前 | 操作後 |
|---|---|
| `- [ ] a` | `- [x] a` |
| `- [x] a` / `- [X] a` | `- [ ] a` |
| `- a` | `- [ ] a` |
| `3. a`(番号は消える) | `- [ ] a` |
| `abc`(リスト行でない) | `- [ ] abc` |
| 空の行(キャレットだけのとき) | `- [ ] ` |

Ctrl+Enter はアクセラレータに登録してあるので、WebView にフォーカスがあるときも効く。

### 4.9 見出しへ移動・行へ移動

**見出しへ移動(Ctrl+Shift+O)**

- 文書中の見出しを、エディタの左上を起点とするポップアップメニューで一覧表示する(専用のダイアログは持たない)。項目を選ぶと、その見出しの行頭にキャレットを置いてスクロールする。最後にフォーカスをエディタに戻す。
- 見出しとみなすのは **ATX 見出しだけ**(Setext 見出しは対象外):
  - 先頭の半角スペースは3つまで。
  - `#`を1〜6個並べ、その直後が半角スペースか行末であること(`#nospace`と`#######`は見出しではない)。
  - 見出し文字列は前後の空白を除いたもの。末尾の`#`の並びは、その前に空白があるときだけ飾りとして取り除く(`### 三 ##` → `三`、`# C#` → `C#`)。
- フェンスで囲んだコードブロックの中の行は除外する。フェンスは字下げ3つまでの行で`` ` ``または`~`を3個以上並べたもの。開いたときと同じ文字が開いたときの個数以上並んだ行で閉じる。閉じないまま文書が終わると、その後ろはすべて除外される。
- 階層は(レベル − 1)個の全角スペースで字下げして表す。空の見出しは「(空の見出し)」と表示し、`&`は`&&`に、タブは空白に置き換える。見出しがなければ、選べない「見出しがありません」だけを出す。

**行へ移動(Ctrl+G)**

- 自前のモーダルダイアログ(タイトル「行へ移動」)をメインウィンドウの中央に開く。ラベル「行番号 (1 - {総行数})」、入力欄、「移動」(既定ボタン)、「キャンセル」。入力欄には今キャレットがある行の番号が全選択で入っている。
- 前後の空白は無視し、全角数字も受け付ける(IME をオンにしたまま打っても通るように)。それ以外の文字、空、負の数、小数は不正。数値は1〜総行数に丸める。
- 入力が不正な間は「移動」を押せず、Enter でも移動しない(`IsDialogMessage`は既定ボタンが無効でも Enter で`IDOK`を送ってくるので、解釈し直して弾く)。
- 移動すると、その行の行頭にキャレットを置いてスクロールし、フォーカスをエディタに戻す。存在しない行番号は最後の行になる。

### 4.10 検索・置換

- Windows 標準の「検索」「置換」ダイアログ(`FindTextW`/`ReplaceTextW`)を**モードレス**で開く。同じ種類が既に開いていればフォーカスを移すだけ、違う種類なら閉じてから開き直す。ダイアログにフォーカスがある間は、メインウィンドウのショートカットは効かない。
- 検索欄の初期値は、エディタで1行に収まる選択(改行を含まず、512 UTF-16単位未満)があればそれ、なければ前回の文字列。検索語・置換語・オプション・方向はセッションの間だけ保持する(初回の方向は「下へ」)。
- **一致の判定**: UTF-16 コード単位の列どうしで比べ、文書の先頭から**重なり合わない**一致を集める。
  - **大文字と小文字を区別しない**: コード単位ごとに Unicode の単純な(1対1の)大文字化をかけて比べる。全角英字も同じ文字として扱う。大文字化すると複数文字になるもの(`ß` → `SS`など)とサロゲートペアの文字は変換しない。
  - **単語単位**: 一致した範囲の直前と直後が、どちらも「単語の文字」でないこと(文書の端は満たす)。単語の文字は Unicode の英数字で、**漢字・かな・全角英数も含む**(`_`は含まない)。そのため、単語の区切りがない日本語の文章の中ではほとんどヒットしない(`日本語の日本`で`日本`は0件)。
- **次を検索**: 「下へ」は選択の終わり以降の最初の一致、「上へ」は選択の始まりより前の最後の一致を選択してスクロールする。見つからなければ反対側の端へ**黙って折り返す**。文書中に1件もなければ「見つかりませんでした」。
- **置換**: 今の選択が検索語と一致するときだけ(大文字小文字の区別はオプションに従い、単語単位は確かめ直さない)置き換え、キャレットを置換後の文字列の直後に置く。続けてそこから下方向に次の一致を選ぶ。
- **すべて置換**: 置換前の本文で全件を確定し、最初の一致から最後の一致までの区間を全件置換した文字列で1回だけ置き換える。元に戻すは1回、プレビューの再描画も1回。置換文字列が検索語を含んでいても再び置換されない。終わったら「N件を置換しました」、0件なら「一致する文字列が見つかりませんでした」。
- 検索語が空なら「検索する文字列を入力してください」。
- 結果は、検索ダイアログを親にしたメッセージボックスで知らせる。エラー通知バーはダイアログの後ろに隠れてしまうため。
- ダイアログは`FINDREPLACEW`構造体とバッファを指すポインタを持ち続けるので、これらは一度だけ確保してアプリの終了まで解放しない。登録メッセージ`FINDMSGSTRING`は別のプロセスからも送れるので、`lparam`が自分の構造体を指しているときだけ処理する。

### 4.11 コードブロックのコピー

- フェンス付きとインデント付きのコードブロックごとに、右上に「コピー」ボタンを付ける。挿入は HTML ではなく AST の上で行う(生HTMLの`<pre>`まで数えると、以降の番号がすべてずれるため)。
- **スクリプトなしで表示する**: ボタンは普段は透明で、ブロックにマウスを乗せるかボタンにフォーカスが入ると現れる。クリックしたときの「コピーしました」の表示も CSS だけで作る(クリックはリンクにフォーカスを与えるが`:focus-visible`にはならないことを使う)。
- ボタンは`mymdedit-copy:<トークン>/<番号>`へのリンク。ネットワークのスキームではないので、リクエストフィルターには当たらない。クリックは`NavigationStarting`で、自前ナビゲーション数を見る**前に**判定し(進行中の描画の通行許可を消費しないため)、アプリ側でコピーしてから必ず取り消す。
- **トークン**は描画のたびに新しく作る乱数。スクリプトが動かないので文書はトークンを知りえず、ボタンを偽造できない。トークンが現在の描画のものと一致し、番号が数値として読めるときだけコピーし、それ以外(偽造・古いページ・形が不正)は記録して無視する。
- クリップボードには、改行を CRLF にそろえ(どの Windows プログラムでも正しく貼り付けられるように)、ブロックの最後の改行を1つ取り除いた文字列を`CF_UNICODETEXT`で置く。失敗したら「コードをクリップボードにコピーできませんでした。」。

### 4.12 ファイル入出力

**ファイル選択ダイアログ**

- **開く**: `IFileOpenDialog`。フィルターは「Markdown / テキスト (*.md;*.markdown;*.txt)」の1つだけ。既定のフォルダはドキュメントだが、`SetDefaultFolder`なので OS が覚えている前回のフォルダが優先される。
- **名前を付けて保存**: `IFileSaveDialog`。フィルターは「Markdown」(`*.md`)のみで、既定の拡張子は`md`。ファイル名欄には今のファイル名の拡張子を除いた部分(新規なら「無題」)を入れる。既存ファイルへの上書き確認はダイアログの既定動作に任せる。文字コード・BOM・改行コードは今の文書のものを引き継ぐ。
- キャンセルされたら何もしない。ダイアログを出せなかったときは「ファイルを開けませんでした。 (…)」/「保存先を選択できませんでした。 (…)」。

**読み込み**

- **上限は64MB**。判定にはファイルが申告する長さではなく、実際に読んだバイト数を使う(読んでいる間に伸びることがあり、デバイスやパイプでは長さに意味がないため)。超えたら「ファイルが大きすぎるため開けません（上限は 64 MB です）。ファイルは変更していません。」。メモリ確保に失敗するとプロセスは panic にもならず abort するので、上限で防ぐ。
- **ディスク上のファイル以外は開かない**。開いたハンドルの`GetFileType`が`FILE_TYPE_DISK`でなければ「通常のファイルではないため開けません（デバイスやパイプは開けません）。」。`CreateFile`は`CON`・`NUL`・COM ポート・名前付きパイプも開いてしまい、それを読むと書き手がいなくなるまで UI スレッドが止まるため。settings.json の読み込みも同じ関数を通る。
- **文字コードは BOM で判定する**。調べる順は UTF-32 LE → UTF-32 BE → UTF-8 → UTF-16 LE → UTF-16 BE(UTF-32 LE の BOM は UTF-16 LE の BOM で始まるので、UTF-32 を先に調べる)。BOM がなければ UTF-8 とみなす。
- **デコードは厳密で、U+FFFD による救済はしない**。U+FFFD を入れて開くと、保存したときに元のバイトを置換文字で上書きして壊してしまう。開かなければ原本は無傷のまま残る。
  - BOM なしで UTF-8 として読めない(Shift-JIS など): 「このファイルは UTF-8 として読み取れませんでした。Shift-JIS など、このアプリが対応していない文字コードの可能性があります。ファイルは変更していません。」
  - BOM 付きの UTF-16/32 が壊れている: 「このファイルは UTF-16 として読み取れませんでした。ファイルが壊れている可能性があります。ファイルは変更していません。」(UTF-32 なら「UTF-32」)
  - デコード後に U+0000 がある(BOM なしの UTF-16 など): 「このファイルには NUL 文字が含まれているため開けません。…」。エディタの Win32 テキスト API は最初の NUL で止まり、残りが表示からも次の保存でファイルからも消えるため。
- **改行コード**: 本文に最初に現れた改行の形(CRLF / LF / CR)を採用する。改行がなければ CRLF。多数決にしないのは、両者が食い違うのは既に改行が混在しているファイルだけで、そのファイルには守るべき元の形がないため。
- 判定した文字コード・BOM の有無・改行コードは`DocumentFormat`として文書に持たせ、保存はこれを必須の引数として受け取る。読み込んだときと違う形で書き戻す経路は作れない。新規文書は UTF-8・BOM なし・CRLF。
- 読み込みに失敗しても、今開いている文書には触らない。開く入口(ダイアログ・最近使ったフォルダ・コマンドライン・読み込み直し)はすべて1か所(`apply_opened`)に集まり、パス・形式・本文・外部変更の記録が別々のファイルを指さないようにしている。

**保存**

- 本文の改行をすべて`DocumentFormat`の改行コードに書き換えてから符号化する。BOM は元のファイルにあった場合だけ付ける。
- 本文に孤立したサロゲートがあると、どの文字コードでも書けないので U+FFFD に置き換えて保存し、「保存しましたが、ファイルに書けない文字（壊れたサロゲート）が含まれていたため U+FFFD（�）に置き換えました。」を出す。
- **保存はアトミック**:
  1. 保存先と同じフォルダに一時ファイル`<ファイル名>.<16桁の16進乱数>.tmp`を新規作成して書き込み、ディスクまで書き出す。同じフォルダに置くのは、差し替えを同じボリューム内で済ませるため。
  2. 保存先がまだなければ、一時ファイルの名前を変える(`MoveFileExW`、上書きなし)。
  3. 保存先があれば`ReplaceFileW`で差し替える(元ファイルの属性と ACL を引き継ぐ)。バックアップ名`<ファイル名>.<乱数>.bak`を必ず渡す。`ReplaceFileW`は元ファイルを退避した後で失敗することがあり、名前を渡さないと元ファイルの行き先が分からなくなるため。失敗したら、元ファイルが消えていればまずバックアップを元の名前に戻し、そのうえで`MoveFileExW`(上書きあり)で差し替えを試みる(`ReplaceFileW`に対応していないファイルシステム向け。属性は引き継がない)。成功したらバックアップを削除する。
  4. 保存先が消えていて一時ファイルだけが残っている場合は、それが唯一のコピーなので消さずに残し、エラーにそのパスを添える。それ以外の場合、一時ファイルは削除する。
- **保存に失敗しても未保存フラグは落とさない**。「保存できませんでした: <パス> (<エラー>)」。名前を付けて保存に失敗したときは、そのパスを文書のパスにしない(一度も書けていない場所を名乗らせないため)。
- 保存に成功したら、未保存フラグを落とし、外部変更の記録を更新し、保存先のフォルダを最近使ったフォルダに加える。
- 読み書きの排他制御(ロック)はしない。外部での変更は4.13の方法で見つける。

### 4.13 外部での変更の検知

- 開いているファイルについて、最後に読み込んだ・保存した・確認した時点の「最終更新時刻とサイズ」を記録しておく。読み込みのときは読む**前**に記録するので、読んでいる途中に入った変更も後で差分として見つかる。
- **ウィンドウがアクティブになるたびに**ディスクと比べる。アクティブ化はフォーカス切り替えの途中なので、メッセージを1つポストして後で比べる。ほかのアプリでの変更が見えるのはそのアプリから戻ってきたときなので、ファイルの監視はしない。アプリ自身のモーダルダイアログが開いているときは比べない(閉じたときの再アクティブ化で比べる)。
- **内容が変わっていた**: まず新しい記録で上書きし(読み込み直しに失敗しても、アクティブにするたびに同じ質問を繰り返さないため)、「{ファイル名} は別のアプリで変更されました。読み込み直しますか?」を出す。ボタンは「読み込み直す」「このまま」で、本文は未保存の変更の有無で変わる(あれば「読み込み直すと、まだ保存していない編集内容は失われます。」)。Esc・×・ダイアログを出せなかった場合は「このまま」。
  - 「読み込み直す」は破棄確認を挟まずに読み込む(失われることは上の本文で伝えている)。失敗したら「ファイルを読み込み直せませんでした: {パス}」に原因を添え、エディタの内容はそのまま残す。
- **ファイルがなくなっていた**(削除・移動): 「開いているファイルが見つかりません（別のアプリで削除または移動されました）: {パス}  保存すると作り直します。」を1回だけ出す。
- **調べられなかった**(ネットワークドライブの切断、共有違反など): 変更なしとして扱う。利用者に打つ手がなく、毎回聞くと煩わしいため。
- **上書き保存の直前にも比べる**。変わっていたら「{ファイル名} は開いたあとに別のアプリで変更されています。上書きしますか?」(上書きする / キャンセル)を出す。
  - キャンセルなら保存せず、未保存のまま残す。断った版は覚えておき、直後の再アクティブ化で同じ変更について「読み込み直しますか」と続けて聞かない。
  - 確認ダイアログを出せなかったときは保存する。断る側に倒すと、その文書を自分のファイルへ保存する手段がなくなるため。
  - ファイルがなくなっていたときは確認せずに保存し、作り直す。

### 4.14 最近使ったフォルダ

- **記録**: ファイルの読み込み(どの入口からでも)と保存に成功したとき、その親フォルダを一覧の先頭に入れる。大文字小文字(Unicode 全体)と末尾の`\`の有無を無視して同じフォルダを除き、最大3件に切り詰める。一覧が変わらないときは設定に書き込まない。
- **表示**: 「ファイル」メニューの「名前を付けて保存」と「終了」の間に区切り線を入れて並べる。左の列がフォルダ名、右の列がフルパス(Win32 のメニューには項目ごとのツールチップがないため)。ドライブのルートなど名前を取り出せないものはフルパスだけ。`&`は`&&`に置き換える。
- **クリックしたとき**:
  1. **フォルダの確認(バックグラウンド)**: 別スレッドでフォルダの一覧を実際に読んでみる(空のフォルダは正常)。切断されたネットワークドライブや名前解決できない UNC パスは、SMB や DNS のタイムアウトまで固まるので UI スレッドでは行わない。確認中にもう一度クリックすると、ビープ音を鳴らすだけ。
  2. **結果**: ほかのモーダルダイアログが開いている間に届いた結果は、閉じるまで処理を待つ。
     - 存在しない: 「このフォルダは見つかりません: {パス}（最近使ったフォルダから削除しました）」を出し、**一覧から削除する**。削除するのはこの場合だけ。
     - アクセス権がない: 「このフォルダにアクセスする権限がありません: {パス}」。一覧には残す。
     - そのほか: 「このフォルダを読み取れませんでした: {パス}（ネットワークドライブが切断されている可能性があります）」。一覧には残す。一時的な原因かもしれない失敗で項目を消すと、復旧後の入口がなくなるため。
  3. **確認に通ったとき**: 破棄確認(4.18)を経て、「開く」と同じダイアログを、そのフォルダを表示した状態で開く(`SetFolder`なので前回のフォルダで上書きされない)。
- 破棄確認をフォルダの確認の**後**、ファイル選択の**前**に置くのは、存在しないフォルダをクリックしただけで保存を促されないようにするため。

### 4.15 設定ダイアログ

「設定を開く...」で、自前のモーダルウィンドウ(タイトル「設定」)をメインウィンドウの中央に開く。表示中はメインウィンドウを無効にし、専用のメッセージループを回す(その間に`WM_QUIT`が届いたら、メインループも終われるように投げ直す)。

- **テーマ**: 「システムの既定 / ライト / ダーク」の選択式コンボボックス。
- **エディタのフォント / プレビューのフォント**: フォント名を入力もできるコンボボックスと、「サイズ」の入力欄+アップダウンの組。
  - 一覧はインストール済みのフォントファミリー(`@`で始まる縦書き用を除き、大文字小文字を区別せず並べ替え・重複除去)。起動時に1回だけ作り、列挙が空なら「Segoe UI」「Consolas」で代用する。
  - 入力されたフォント名は前後の空白を削るだけで、インストールされているかは確かめない。
  - サイズの範囲は8〜48。小数も入力できる。数値でない値(空欄、`abc`、`inf`など)は**その項目の変更前の値**に戻し、範囲外の値は8〜48に収める。
- **プレビュー背景色**: 「背景色をカスタマイズする」チェックボックス、「色を選択」ボタン(チェックがオンのときだけ押せる)、色見本。「色を選択」で Windows 標準の「色の設定」ダイアログ(`ChooseColorW`)を、今の背景色と16枠のカスタムカラーを渡して開く。保存の時点でチェックがオフなら、背景色はテーマの既定になる。
  - **カスタムカラーは、色の設定ダイアログを閉じた時点で、OK でもキャンセルでも設定に保存する**。設定ダイアログを保存するかどうかとは関係ない。標準の色ダイアログ自体が、キャンセルされてもカスタムカラーの編集を残すので、それに合わせている。
- **表(テーブル)**: 「ヘッダー行をグレー背景にする」「データ行を1行おきにグレー背景にする(縞模様)」の独立した2つのチェックボックス。
- **保存 / キャンセル**: 「保存」は既定ボタン。「キャンセル」・Esc・×は何も反映せずに閉じる。
- 保存した内容は、ダイアログを開いた時点ではなく**保存を押した時点の設定**に重ねる。ダイアログを開いている間にカスタムカラーが保存されているので、開いた時点の値に重ねるとそれが消えるため。差し替えるのはテーマ・フォント2組・背景色・表の2項目だけで、最近使ったフォルダとカスタムカラーはそのまま引き継ぐ。
- 表示に関わる値が変わっていれば、テーマ・エディタのフォント・プレビューをその場で反映し直す(再起動は要らない)。
- ダイアログの配色は開いた時点のテーマに従う。ダークのときは、チェックボックスだけテーマを外して自前の文字色で描く(テーマ付きのチェックボックスは`WM_CTLCOLORBTN`を無視して黒い文字で描くため)。
- ダイアログを出せなかったときは「設定ダイアログを表示できませんでした。」。

### 4.16 起動時の引数・多重起動

- コマンドラインの**最初の引数だけ**を開くファイルとして扱う。エクスプローラーでダブルクリックしたときも、この形で渡される。アプリ側ではファイルの関連付けを登録しない(MSIX を使わないため。README に「プログラムから開く」での設定方法を書いている)。
- 起動時はまずサンプル文書を読み込み、そのあとで引数のファイルを開く。開けなかったときはサンプル文書(無題.md)のまま、「ファイルを開けませんでした: {パス}」に原因を添えて出す。
- 多重起動は抑止しない。起動するたびに新しいプロセスとウィンドウができる。設定ファイルは共有するが、書き込むたびに読み直して変更分だけを当てるので、互いの変更を消し合わない(5章)。
- 起動そのものに失敗したとき(ウィンドウを作れないなど)は、「MyMDedit を起動できませんでした。」に原因を添えたメッセージボックスを出して終了する。

### 4.17 ウィンドウタイトル

タイトルは「{ファイル名}」、未保存の変更があれば「{ファイル名} *」。アプリ名は付けない。新規作成時と起動直後は「無題.md」。未保存の印が付くのは利用者の編集だけで、アプリ自身が本文を置き換えたときは付かない(4.1)。保存に失敗したときは印を消さない。

### 4.18 未保存の変更の破棄確認

- 未保存の変更があるときに文書を置き換える操作やアプリを閉じる操作をすると、TaskDialog で確認する。見出し「変更を保存しますか?」、本文「編集内容が保存されていません。」、ボタン「保存する」(既定)「保存しない」「キャンセル」。Esc と×は「キャンセル」。
- 対象: **新規**、**開く**、**最近使ったフォルダから開く**、**起動引数のファイル**(起動直後なので実際には出ない)、**終了**メニュー、**ウィンドウを閉じる操作**(×・Alt+F4・タスクバー。どれも`WM_CLOSE`)、**サインアウト・シャットダウン・Restart Manager**(`WM_QUERYENDSESSION`)。外部での変更による読み込み直しは対象外(4.13)。
- 「保存する」は「保存」と同じ処理をする。終わっても未保存のままなら(保存に失敗した、保存先の選択をキャンセルした、外部変更の上書きを断った)、置き換えも終了も行わない。
- 確認ダイアログそのものを出せなかったときは、**ウィンドウを閉じる操作のときだけ閉じる側**、それ以外は中止する側に倒す(閉じられないウィンドウを作らないため)。
- 自分のモーダルダイアログが開いているときに閉じる要求が来ても無視する(確認を重ねないため)。
- **サインアウト・シャットダウン**は`WM_CLOSE`を経由しない。既定の処理は「終了してよい」と答えて未保存の内容が失われるので、`WM_QUERYENDSESSION`でも確認する。
  - 未保存の変更があれば、シャットダウン画面に出る理由「保存されていない変更があります」を登録してから確認を出す。
  - ほかのモーダルダイアログが開いているとき、または確認を出せなかったときは、破棄せずに終了を拒む(利用者はシャットダウン画面で事情を知り、そこで選べる)。
  - 許可したら登録した理由を取り消す。`WM_ENDSESSION`で終了が取りやめになったときも取り消す。

### 4.19 エラー通知とログ

- 利用者に見せる失敗の通知先は、ツールバーの直下の**エラー通知バー**1か所。左にエラーのアイコン、中央に本文(折り返す)、右端に「閉じる」ボタン。
- 通知は積み重ね、最新の**3件まで**を改行で区切って表示する。直前と同じ文言は重ねない(フォルダがなかったことと、その削除を設定に書き込めなかったことのように、2つの失敗が続けて起き、どちらも読む価値があるため)。
- 通知は利用者が「閉じる」を押すまで残る。押すとすべての通知を消してバーを畳む。
- 通知する主なもの: 設定の読み込みの警告(5章)と保存の失敗、ファイルの読み込み・保存の失敗、最近使ったフォルダを開けなかったこと、開いているファイルが消えたこと、各ダイアログを開けなかったこと、コードのコピーの失敗、WebView2 の初期化失敗・プロセスの停止・プレビューの更新失敗。
- 握りつぶすエラーはすべて`log::error`で`[MyMDedit] ERROR <場所>: <内容>`として`OutputDebugStringW`に記録する(デバッグビルドでは標準エラーにも出す)。リリースビルドでも DebugView などで追える。安全に縮退でき利用者の対処が要らない失敗(確認ダイアログを出せなかった、ディスク上の状態を調べられなかった、プレビューで遮断したもの、など)は記録だけにする。
- **panic**: 起動の最初に panic フックを入れ、`[<UNIX秒>] panic: <内容と発生位置>`を`OutputDebugString`と`%LOCALAPPDATA%\MyMDedit\crash.log`(追記)に書く。リリースビルドはコンソールがなく strip もしているので、これが唯一の手がかりになる。panic の多くは`extern "system"`のコールバック内で起き、そこではプロセスが abort して利用者には何も表示されない。

### 4.20 テーマ

- 設定は「システムの既定 / ライト / ダーク」。「システムの既定」では、レジストリの`AppsUseLightTheme`が0のときだけダークにする(読めなければライト)。
- 色はダーク・ライトそれぞれ固定のパレットで決める。Win32 には一度に切り替えるスイッチがないので、部位ごとに別の仕組みで追従させる。
  - **タイトルバー**: DWM の`DWMWA_USE_IMMERSIVE_DARK_MODE`。
  - **ポップアップメニュー・スクロールバー**: uxtheme の序数135`SetPreferredAppMode`と序数136`FlushMenuThemes`(非公開。古い OS では黙って効かない)。
  - **メニューバー**: どのテーマも面倒を見ないので、ダークのときだけ非公開のメッセージ`WM_UAHDRAWMENU`/`WM_UAHDRAWMENUITEM`で自前で描く。メニューバーの下に非クライアント描画が引く明るい1px線は、`WM_NCPAINT`/`WM_NCACTIVATE`の後で塗りつぶす。
  - **エディタ・ツールチップ**: `AllowDarkModeForWindow`(序数133)と`SetWindowTheme`(`DarkMode_Explorer`など)。
  - ツールバー・通知バー・フッターは自前描画でパレットの色を使う。エディタの背景と文字色、WebView2 の既定の背景色(ダーク`#1E1E1E`、ライト`#FFFFFF`)、プレビューの CSS(4.2)、自前のダイアログ(設定・行へ移動)もパレットに従う。
- テーマを変えたら、メニューバーと非クライアント領域を描き直させ、本体・エディタのフォント・プレビューを作り直す。
- テーマが「システムの既定」のときは、OS のライト/ダークの切り替え(`WM_SETTINGCHANGE`の`ImmersiveColorSet`)に追従する。

### 4.21 高DPI

- マニフェストで Per-Monitor V2 の DPI 対応を宣言する。寸法はすべて DIP で持ち、ウィンドウの DPI で換算する。
- DPI が違うモニターへ移したとき(`WM_DPICHANGED`)は、フォント(UI・太字・アイコン・メニュー)を作り直し、OS が示した大きさにウィンドウを合わせてから、レイアウトをやり直す。UI のフォントには、その DPI でのシステムのメッセージフォントとメニューフォントを使う。

## 5. データモデルと永続化

設定は`%APPDATA%\MyMDedit\settings.json`に1つの JSON オブジェクトとして保存する。現在の設定(`AppSettings`)を持つのは`SettingsStore`だけで、書き込みは`SettingsStore::update(|s| …)`を通す。上下限は`settings::limits`にだけ書き、ダイアログのアップダウンも補正の処理もそこを参照する。

| JSON キー | 型 | 既定値 | 上下限・読み込み時の検証 |
|---|---|---|---|
| `theme` | `"System"` / `"Light"` / `"Dark"` | `"System"` | ほかの値なら既定値 |
| `editor_font_family` | 文字列(カンマ区切り) | `"Cascadia Mono, Consolas"` | なし(使うときにインストール済みの最初の候補を選ぶ) |
| `editor_font_size` | 数値 | `14` | 8〜48に収める |
| `preview_font_family` | 文字列(カンマ区切り) | `"Segoe UI, sans-serif"` | なし(CSSに入れるときに4.2の処理をする) |
| `preview_font_size` | 数値 | `15` | 8〜48に収める |
| `preview_background_color` | `#RGB` / `#RRGGBB`、または`null` | `null`(テーマの既定) | 書式が違えば`null`。CSSに入れる直前にも検証する |
| `recent_folders` | 文字列の配列 | `[]` | 空文字列を除き、3件まで |
| `custom_colors` | 文字列の配列(`#RGB`/`#RRGGBB`) | `[]` | 書式の違うものを除き、16件まで |
| `table_header_gray_background` | 真偽値 | `false` | |
| `table_row_striping` | 真偽値 | `false` | |

- ファイルの上限は1MB。普通の設定ファイルは4KBを大きく下回る。アプリの外から書き換えられるファイルなので、読めないほど大きなものを置かれて毎回の起動が abort するのを防ぐ。
- 書き出しは整形した JSON を UTF-8・BOM なし・LF で、文書と同じアトミック保存(4.12)で行う。フォルダがなければ作る。
- **読み込み**: 先頭の BOM は読み飛ばし、UTF-8 として正しくなければ置換文字で救済しない。**項目ごとに読む**ので、型が違う項目だけを既定値に戻し、ほかの項目は生かす。知らないキーは無視する(保存するのは`AppSettings`の項目だけなので、次の保存で消える)。範囲外のサイズや書式の違う色など、補正した値も「読めなかった項目」として扱う。
- **壊れたファイルの扱い**:
  - JSON オブジェクトとして読めない(構文エラー、配列、UTF-8 でない、1MB 超)ならすべての項目を、一部の項目だけ読めないならその項目を既定値にする。どちらの場合も、次の保存で原本が上書きされる前に`settings.broken-<UNIX秒>.json`へコピーして退避し、起動後に「設定ファイルを読み込めなかったため、既定の設定で起動しました。元のファイルは <パス> に保存してあります。」または「一部の項目（<キー名>）を読み込めなかったため、既定値を使います。…」を出す。退避に失敗したら、その起動中は設定を書き込まない。
  - ファイルがなければ、何も言わずに既定値で起動する。
  - それ以外の読み込みエラー(ロック、権限など)は一時的なものとみなし、ファイル自体は正常かもしれないので、その起動中は書き込まない(「…元のファイルを守るため、この起動中は設定を保存しません。」)。
  - 設定の読み込みは UI ができる前に走るので、警告はウィンドウを作った後で通知バーに出す。
- **複数インスタンス間の同時書き込み**: `update`は名前付きミューテックス`Local\MyMDedit.Settings`を取ってから、ディスク上の設定を読み直し、渡された変更だけを当てて書き戻す。別のインスタンスがほかの項目に加えた変更が残る。待つのは最大2秒で、待ち切れなければそのまま書く(固まったインスタンスに巻き込まれないため)。読み直しで別インスタンスの表示設定を取り込んだときは、画面にも反映する。
- **書き込みの失敗**: 失敗しても現在の設定は新しい値にする(画面と食い違わないように)。利用者に知らせるのは`App::persist_settings`だけで、「設定を保存できませんでした。この変更は次回の起動時には元に戻ります。」を出す。
- **保存しないもの**: ズーム倍率、ウィンドウの位置と大きさ、検索語と検索オプション。
- そのほかの保存場所: WebView2 のデータは`%LOCALAPPDATA%\MyMDedit\WebView2`(InPrivate なので閲覧の記録は残らない)、panic の記録は`%LOCALAPPDATA%\MyMDedit\crash.log`。

## 6. アーキテクチャ概要

すべての状態は`App`にあり(`ui: Cell<Ui>`にハンドル、`state: RefCell<State>`、`preview: RefCell<Preview>`)、ウィンドウプロシージャからはスレッドローカルの`app()`で参照する。

- `main.rs` — エントリポイント。DLL 検索の制限、panic フック、COM(STA)とコモンコントロールの初期化、コマンドライン引数。
- `app.rs` — メインウィンドウ、メニュー・ツールバー・通知バー・フッター、すべてのコマンド。アクセラレータの一覧`ACCELERATORS`(メインのアクセラレータテーブルと WebView からの転送の両方が使う)。
- `editor.rs` — RichEdit のラッパー(4.1)。
- `md_ops.rs` / `search.rs` — 記法挿入・リスト継続・字下げ・タスク・見出しの抽出、検索・置換。どれも1つの`Edit`(置き換える範囲1つ + その後の選択)を返す純粋関数なので、各操作が元に戻す1回になる。
- `render.rs` — Markdown → HTML 文書(CSP・CSS・取得系要素の無効化・コピーボタン)。
- `preview.rs` — WebView2 のホストと安全対策のハンドラー(4.3)。
- `document.rs` / `line_endings.rs` — 文字コード・BOM・改行の判定、読み込みの制限、アトミック保存、外部変更の記録。改行の定義は`line_endings.rs`の1か所だけ。
- `settings.rs` / `settings_dialog.rs` — 設定の読み書き(5章)と設定ダイアログ。
- `dialogs.rs` / `goto_dialog.rs` — ファイル選択・確認・色の設定ダイアログ、フォントの列挙、行へ移動。
- `theme.rs` — ダークモード(4.20)。
- `win.rs` / `log.rs` — Win32 の小さなヘルパー、エラーの記録(4.19)。

テストは純粋ロジックのモジュール(`md_ops`・`search`・`document`・`line_endings`・`settings`・`render`・`dialogs`の解析処理・設定ダイアログの入力処理)と、ビルドした exe の PE ヘッダー(安全対策のリンク設定)に対する単体テスト。`fuzz/`に純粋ロジックのファズテスト、`tests/security/`にプレビューのセキュリティ回帰テストがある。Win32・WebView2 を経由する部分は実機で確かめる。

## 8. 既知の制約・プラットフォーム固有の注意点

- **`RefCell`の借用を、ウィンドウプロシージャに再入しうる呼び出しの間持ち続けてはならない**。モーダルダイアログ(ファイル選択、TaskDialog、MessageBox、設定ダイアログ)、エディタへの`SendMessage`(`EN_CHANGE`を同期的に送り返す)、WebView2 の呼び出しが該当する。違反はコンパイルエラーではなく、実行時の`BorrowMutError`の panic になる。必要な値を取り出して借用を落としてから呼ぶ。
- Win32/COM に渡すバッファは、読まれる呼び出しより長く生かす。API がポインタを持ち続ける場合はさらに長く(検索ダイアログの`FINDREPLACEW`はアプリの寿命の間)。
- RichEdit は Enter の改行を`WM_KEYDOWN`で入れる(4.8)。既定の文字数の上限は32K、`EM_SETTEXTMODE`は空のときしか効かない、`EM_SETTEXTEX`と`EM_SETCHARFORMAT`は`EN_CHANGE`を出しうる(4.1)。
- WebView にキーボードフォーカスがあると、キーはメインのアクセラレータテーブルに届かない。`AcceleratorKeyPressed`で同じ一覧を引いて転送する。
- メニューバーにはダークテーマがなく、非公開の UAH メッセージで描く。ポップアップメニューは uxtheme の非公開の序数に頼る(4.20)。
- WebView2 はイベントハンドラーの`Err`を無視して既定の動作を続ける。安全対策のハンドラーで判定前に`?`で抜けると通す側に倒れる(4.3)。
- `NavigationStarting`はポップアップを見ず、取り消してもネットワークのリクエストは止まらない。外へ出てはならないものは`WebResourceRequested`で止め、リクエストを伴わない接続(`dns-prefetch`など)は文書の中身から要素を除く(4.3)。プレビューの処理に手を入れたら`tests/security/`で確かめ直す。
- **DLL は System32 からだけ読む**。exe の隣(ダウンロードフォルダなど)に置かれた`dwmapi.dll`や`Msftedit.dll`が読み込まれていたため、3つの設定で防ぐ。① `main`の最初、ほかの何よりも先に`SetDefaultDllDirectories(LOAD_LIBRARY_SEARCH_SYSTEM32)`(名前での読み込みすべてに効き、システム DLL が代わりに行うものも含む)、② 静的インポートは`main`より前に解決されるので、リンカーの`/DEPENDENTLOADFLAG:0x800`、③ C ランタイムの静的リンク(VCRUNTIME140.dll に依存しない)。②と③は単体テストがビルドした exe で確かめる。
- 攻撃緩和策として Control Flow Guard と CET シャドウスタック互換(`/CETCOMPAT`)を有効にしている。ASLR(高エントロピーを含む)と NX はリンカーの既定。単体テストが PE ヘッダーで確かめる。
- プレビューのページは文書全体を収めた`data:` URI なので、WebView2 のプロファイルは InPrivate にする(4.3)。InPrivate なしでコントローラーを作らない。
- `ReplaceFileW`は元ファイルを退避した後で失敗することがあるので、必ずバックアップ名を渡し、保存先が消えている間は一時ファイルを消さない(4.12)。
- `NavigateToString`には約2MBの上限がある(4.2)。
- マニフェストでは Common Controls v6(TaskDialog と全標準コントロールのビジュアルスタイルに必要)、Per-Monitor V2、`longPathAware`を宣言している。
