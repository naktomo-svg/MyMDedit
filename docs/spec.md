# MyWinApp 仕様書(現時点)

最終更新: 2026-08-06。本書は `master` ブランチ時点(コミット `0323633`)の実装内容から起こした、現状の機能仕様書。個々の機能追加の設計判断・検討経緯は `docs/superpowers/specs/` 配下の各設計書を参照(本書はそれらの集約版であり、詳細な実装コード片は原則載せない)。

## 1. 概要

MyWinAppは、Windows向けのシンプルなMarkdownエディタ(WinUI 3デスクトップアプリ)。ウィンドウ左側でMarkdownを編集すると、右側にHTMLプレビューがリアルタイムに表示される、左右分割の単一ウィンドウ構成。

## 2. 動作環境・技術スタック

- Windows 10 バージョン1809(10.0.17763.0)以降(`TargetPlatformMinVersion`)。ビルド/テスト対象は10.0.26100.0 SDK。
- [WebView2ランタイム](https://developer.microsoft.com/microsoft-edge/webview2/)が必要(HTMLプレビュー表示用。多くのWindows環境には既定でインストール済み)。
- WinUI 3 / Windows App SDK 2.3.1、.NET(`net10.0-windows10.0.26100.0`)、MSIXパッケージ形式のデスクトップアプリ(`runFullTrust`)。
- 対応アーキテクチャ: x86 / x64 / ARM64。
- 主要ライブラリ: [Markdig](https://github.com/xoofx/markdig) 1.3.2(Markdown→HTML変換、`UseAdvancedExtensions()`有効)、[CommunityToolkit.Mvvm](https://github.com/CommunityToolkit/dotnet) 8.4.2(MVVM)、`System.Drawing.Common`(インストール済みフォント列挙用)。
- `dotnet run`はMSIXパッケージIDを登録して起動するため(`Microsoft.Windows.SDK.BuildTools.WinApp`)、WinUI3/MSIX依存機能(ファイル関連付け、`ApplicationData.LocalSettings`等)が正しく動作する。`bin/`配下の生exeを直接起動した場合は動作しない。

## 3. 画面構成

単一ウィンドウ(`MainWindow`)。タイトルバーはアプリがカスタム描画(`ExtendsContentIntoTitleBar`、`MicaBackdrop`)。中身は`Frame`が`MainPage`に一度だけ`Navigate`する構成で、以降の画面遷移はない。

`MainPage`は縦3行のグリッド:

1. **メニューバー + Markdown記法ツールバー**: 左に`MenuBar`(ファイル / 編集 / 検索 / 設定)、右にMarkdown記法挿入ツールバー(4.4参照)を横並びで表示
2. **本体**: 左にMarkdownエディタ(`TextBox`)、中央に1px区切り線、右にHTMLプレビュー(`WebView2`)の左右分割
3. **フッター(ステータスバー)**: 行数・文字数・ズーム倍率を常時表示

## 4. 機能仕様

### 4.1 エディタ / プレビュー

- 左ペインは複数行`TextBox`(`AcceptsReturn="True"`、折り返しあり、スクロールバー自動表示)。起動時はサンプルのMarkdown文書が表示される。
- 編集内容は1文字入力されるごとに(`UpdateSourceTrigger=PropertyChanged`)Markdig経由でHTMLに変換され、右ペインの`WebView2`に`NavigateToString`で反映される(リアルタイムプレビュー、デバウンスなし)。
- プレビューのHTMLは生成のたびに完全なHTMLドキュメント(`<html><head><style>...</style></head><body>...</body></html>`)として組み立てられ、`AppSettings`から導出したCSS(後述)が埋め込まれる。Markdownの生HTML(HTMLタグの直書き)は**描画上はサニタイズされず素通しする**(HTMLタグはHTMLとして解釈される)が、実行と外部通信は次の3層で封じている。ファイル関連付けにより第三者が書いた`.md`を開く経路が実在するため。
  - `CoreWebView2Settings.IsScriptEnabled = false` — 文書内のスクリプト(`<script>`、`onerror=`等のインラインイベントハンドラ、`javascript:`URI)を実行しない。プレビューのズームが使う`ExecuteScriptAsync`はこの設定の影響を受けない旨が公式に明記されているため、ズームは動作する(4.2参照)。
  - CSP`<meta>` (`default-src 'none'; img-src data: https:; style-src 'unsafe-inline'; base-uri 'none'; form-action 'none'`) — リモートのCSS・フォント・フレーム・ネットワーク要求を遮断する。**画像は`https:`とdata URIのみ許可**しており、平文`http://`の画像URLはプレビューに表示されない。リモート画像を許可しているのは4.4の画像挿入ボタンの出力を活かすためで、引き換えに「ファイルを開いた事実」が画像の取得元に伝わりうることを許容している(このアプリはCookieや認証情報を持たないため、漏れるのはその事実のみ)。
  - `CoreWebView2.NavigationStarting`での遷移ガード — **アプリ自身が開始した遷移だけを通す**。CSPはfetchを統制するがナビゲーションは統制しないため、`<meta http-equiv="refresh">`・`<form action>`・`<base href>`・リンククリックによる離脱をここで塞ぐ。判定は次の2つの条件の**論理積**であり、いずれも`e.Uri`の**形を当てにしない**。
    - **アプリ自身の遷移かどうか**: `NavigateToString`を呼ぶ直前に加算し、`NavigationStarting`到着時に減算する「実行中の自前ナビゲーション数」がゼロなら取り消す(キーストロークごとに再描画するため同時に複数が飛びうる。boolでは先着1件に消費されて後続の正当な再描画まで取り消されるので、カウンタで持つ)。
    - **スキームの拒否リスト**: `http:` / `https:` / `file:` / `ftp:` / `ws:` / `wss:`(大文字小文字を区別しない)で始まるURIは、上記カウンタの値によらず取り消す。`NavigateToString`が生成しえないスキームなので、文書側が仕掛けた遷移でしかありえない。`NavigateToString`は非同期のためカウンタが正のままメッセージループを1周する隙があり、その間に届いた敵対的な遷移をカウンタだけでは自前の再描画と区別できない。またカウンタが何らかの理由で戻り損ねると、カウンタだけのガードは以後セッション中ずっと無警戒に開いたままになる。この拒否リストはその両方に対する2段目の防御である。
    - この2条件は**加算のみの関係**であり、拒否リストが単独で「通す」根拠になることはない。`e.Uri`の形に対する**許可リストに書き換えてはならない**: 以前`about:blank`を期待する許可リストにしていたところ、実測(WebView2 150.0.4078.105)では`NavigateToString`は`Uri="data:text/html;charset=utf-8;base64,…"`で`NavigationStarting`を発火し(`about:blank`は生成される文書の**原点**であって、このイベントのURIではない)、アプリ自身の再描画が全て取り消されてプレビューが真っ白になる不具合を起こした。スキームの拒否リストは、将来ランタイムがどんな形のURIを渡してきても自前の再描画を取り消しえないため、追加しても同じ失敗を再現しない。
    - ガードが遷移を取り消したときは、その事実とURI(先頭200文字まで)を`PreviewNavigationBlocked`として記録する(4.12参照)。`NavigationCompleted`側の記録では、ほぼ毎キーストロークで発生する「新しい描画に追い越された」ケースと区別がつかないため。
- ウィンドウタイトルにファイル名と未保存インジケーター(末尾`*`)を表示(4.10参照)。
- エディタの縦スクロール位置は**割合でプレビューに連動する**(エディタ→プレビューの一方向。プレビューを直接スクロールしてもエディタは動かない)。エディタ内部の`ScrollViewer`の`ViewChanged`から`VerticalOffset ÷ (ExtentHeight - ViewportHeight)`を0〜1で求め、`ExecuteScriptAsync`でプレビューの`scrollTop`に適用する(`Services/PreviewScrollSync.cs`)。
  - 割合方式のため、エディタとプレビューで高さの対応が一致しない箇所(画像、コードブロック、表)ではずれる。先頭と末尾は一致する。
  - プレビューは1文字ごとに`NavigateToString`で作り直され、そのたびにスクロール位置が先頭へ戻るため、`NavigationCompleted`で保持中の割合を再適用する。ズーム(4.2)も文書の高さを変えるので、ズーム適用後にも再適用する。**適用順序はズーム→スクロールに固定**されている(順序が逆だとズームによる高さ変化の分だけずれる)。
  - `ViewChanged`はドラッグ中に連続発火するため、`ExecuteScriptAsync`が実行中は最新の割合だけを保持し、完了後に1回だけ流す(タイマーによる間引きではなく、WebView2の処理速度に自動で追従する方式)。
  - 検索ダイアログによるエディタのスクロール(4.7)も`ViewChanged`を発火させるので、検索結果へのジャンプにプレビューが追従する。

### 4.2 ズーム

- エディタ・プレビュー双方のフォント表示サイズを50%〜200%(10%刻み、既定100%)で連動して拡大縮小する、セッション限定の機能(設定には保存されず、アプリ再起動のたびに100%へリセットされる)。
- 操作方法:
  - **Ctrl+マウスホイール**(エディタ上にポインタがある場合のみ)
  - **Ctrl+ "+"**(テンキー`Add`、メインキー`OemPlus`、および日本語キーボード等でShiftを要する配列向けにCtrl+Shift+OemPlusの3系統いずれでも)
  - **Ctrl+ "-"**(テンキー`Subtract`、メインキー`OemMinus`)
  - **Ctrl+0**(メインキー`Number0`、テンキー`NumberPad0`)いずれもリセットして100%に戻す
  - これらのキーボードショートカットはウィンドウ全体で有効(エディタ・プレビューどちらにフォーカスがあっても機能する)
- エディタのフォントサイズは`設定`のエディタフォントサイズ×ズーム倍率で実効表示される。
- プレビュー側のズームはCSSの`document.body.style.zoom`をJavaScript注入(`CoreWebView2.ExecuteScriptAsync`)で適用する方式(WinUI3のXAML `WebView2`はネイティブズームAPI `CoreWebView2Controller`を公開していないため — 8章参照)。プレビューの再描画(`NavigateToString`)のたびに再適用される。再適用は必ずズーム→スクロール位置(4.1)の順で行われる。
- プレビュー領域上でのCtrl+マウスホイールはWebView2のネイティブズーム機構が無効化されている(`IsZoomControlEnabled = false`)ため、何も起きない。プレビューのズームはエディタ上の操作か全体ショートカットに一本化されている。

### 4.3 フッター(ステータスバー)

常時、以下3項目を表示(選択範囲ではなく文書全体が対象、編集のたびにリアルタイム更新):

- **行数**: 改行(`\r\n`・`\r`・`\n`いずれも1つの改行として計算)区切りの要素数。空文書は1行。
- **文字数**: `string.Length`(UTF-16コード単位。サロゲートペア文字は2文字としてカウント)。
- **ズーム倍率**: 4.2のズーム倍率(%)。

カーソル位置(行・列)や選択範囲の文字数は表示しない(対象外)。

### 4.4 メニューバー

#### ファイル
- **新規**(Ctrl+N): 現在のファイルパスを破棄し、サンプル文書に戻す(ファイル名は「無題.md」に戻る)。未保存の変更がある場合は破棄確認を経る(4.11参照)。
- **開く**(Ctrl+O): OSのファイル選択ダイアログ(`FileOpenPicker`、フィルタ`.md`/`.markdown`/`.txt`、初期フォルダはドキュメントライブラリ)。
- **保存**(Ctrl+S): 既存ファイルへ上書き保存。未保存(新規作成後など)の場合は「名前を付けて保存」にフォールバック。
- **名前を付けて保存**(Ctrl+Shift+S): OSの保存ダイアログ(`FileSavePicker`、拡張子`.md`固定、初期フォルダはドキュメントライブラリ)。
- **最近使ったフォルダ**(区切り線の下に動的追加、最大3件): 直近にファイルを開いた/保存したフォルダをフォルダ名で表示(フルパスはツールチップ)。クリックすると、そのフォルダを表示した状態でOS標準のファイル選択画面が開く(「開く」と同じ画面・同じフィルタ。後述4.6)。
- **終了**(Alt+F4): アプリケーションを終了する。未保存の変更がある場合は破棄確認を経る(4.11参照)。

#### 編集
`元に戻す`(Ctrl+Z)/`やり直し`(Ctrl+Y)/`切り取り`(Ctrl+X)/`コピー`(Ctrl+C)/`貼り付け`(Ctrl+V)/`すべて選択`(Ctrl+A) — いずれもエディタの`TextBox`標準操作を呼び出すのみ(メニュー項目の`KeyboardAcceleratorTextOverride`は表示用ラベルであり、実際のショートカットは`TextBox`既定の挙動に依存)。実行後、フォーカスはエディタへ戻る。

#### 検索
- **検索...**(Ctrl+F)/**置換...**(Ctrl+H): いずれも同じ検索・置換ダイアログを開く(後述4.7)。

#### 設定
- **設定を開く...**: 設定ダイアログを開く(後述4.8)。

#### Markdown記法ツールバー
メニューバーの右隣に、クリックするだけでMarkdown記法をエディタに挿入できるツールバーを表示する。基本セット(常時表示、7ボタン): 太字・斜体・見出し(H1/H2/H3を選ぶドロップダウン)・箇条書きリスト・番号付きリスト・リンク・インラインコード。拡張セット(「その他」ドロップダウン、6項目): 引用・水平線・画像・テーブル・取り消し線・コードブロック。各ボタンには挿入される記法を明示したツールチップが付く(記法を知らない人でも使える設計)。

- **インライン囲み系**(太字・斜体・取り消し線・コード・コードブロック): テキスト選択中は選択範囲を記法で囲み、囲んだ後も元のテキスト部分を選択状態に保つ。未選択時はプレースホルダー入り記法を挿入し、プレースホルダー部分を選択状態にして即座に上書き入力できるようにする。
- **リンク・画像**: `[テキスト](url)` / `![代替テキスト](url)` の形で挿入し、挿入後は常に`url`部分を選択状態にする(コピー済みURLをそのまま貼り付けられるようにするため)。なお画像がプレビューに表示されるのは`https:`とdata URIの場合のみで、平文`http://`のURLは表示されない(4.1のCSP参照)。
- **見出し・箇条書きリスト・番号付きリスト・引用**(行頭付与系): 見出しは対象行1行のみ、箇条書き・番号付きリスト・引用は選択が及ぶ全行の行頭に記法を付与する。番号付きリストは対象行に`1.`から始まる連番を振る。挿入後は記法自体を選択状態にはせず、キャレットのみを残す(未選択時はカーソル位置を挿入した記法の文字数分だけ後ろにずらし、選択時は書き換えたブロック全体の末尾にキャレットを置く)。
- **水平線・テーブル**(ブロック挿入系): 独立した行になるよう改行を補い、前後に空行を確保して挿入する(Markdigでの描画崩れ防止)。テキスト選択中に実行すると、選択範囲は挿入したブロックで置き換わる。
- 記法のトグルオフ(2度押しで記法を除去)・ツールバーの折り返し/オーバーフロー処理は非対応。

**Enterキーによるリスト自動継続**: 箇条書き(`- `)・番号付き(`N. `)の行末でEnterを押すと、次の行に同じ記法(番号は直前行の数値+1)が自動挿入される。マーカーのみで本文がない行(例: `- `だけの行)でEnterを押すと、マーカーが削除され通常の改行になる(リストからの脱出)。引用のEnter自動継続は非対応。カーソルが記法(マーカー)より前にある状態でのEnterは自動継続の対象外で、通常のEnterのまま動作する。選択範囲がある状態でのEnterにはこの機能は一切介入しない。番号付きリストの連番は直前行の数値に単純に+1するだけで、行の並べ替えやリストの途中への挿入には追随しない。

**見出しレベルの相互切り替え**: 見出しボタン(H1/H2/H3)を押したとき、対象行に既に見出し記法(`#`〜`######`、H6まで検出)があれば、それを取り除いてから新しいレベルの記法を付け直す(積み重ならない)。箇条書き・番号付きリスト・引用との相互置き換えは非対応(見出し間のみ)。同じレベルの再クリックは実質no-op。

### 4.5 ファイル入出力

- 対応拡張子: `.md` / `.markdown` / `.txt`(開く操作・最近使ったフォルダからの選択いずれも)。保存は`.md`固定。
- **文字コードの往復保持**: 読み込み時にBOMから文字コードを判定し(UTF-8 / UTF-16 LE・BE / UTF-32 LE・BE、BOMなしはUTF-8とみなす)、その判定結果を文書の属性(`DocumentFormat`)として保持して、保存時に同じ文字コード・同じBOM有無で書き戻す。UTF-8 with BOMのファイルを開いて保存してもBOMは維持される。
- **改行コードの往復保持**: 読み込んだ本文に最初に現れる改行から改行コード(CRLF / LF / CR)を判定し、`DocumentFormat.LineEnding`として同じく保持して、保存時に本文中の全ての改行をその形へ書き戻す(`Services/LineEndings.cs`)。改行を1つも含まないファイル、およびディスクから読んでいない新規文書はCRLFとして扱う。
  - そもそも保存時に改行を書き換える必要があるのは、WinUI3の`TextBox`(`AcceptsReturn="True"`)がユーザー入力の改行を`\r`のみで保持するため(そのまま書き出すとCRが混在したファイルになる)。
  - 判定を「最初の改行」で行い多数決を採らないのは、両者が食い違うのは既に改行が混在しているファイルだけであり、そのファイルには保つべき原形がないため(どちらを選んでも保存時に残りは書き換わる)。
  - 以前は`Environment.NewLine`(Windows環境ではCRLF)固定で書き出していたため、LF改行のファイルを1行編集して保存すると全行が書き換わった差分になっていた。
- **非UTF-8ファイルは開かない**: BOMがなくUTF-8としてデコードできないファイル(日本語環境のShift-JIS `.txt`など)は、読み込みを拒否してエラー通知(4.12参照)を出し、現在の文書はそのまま維持する。このアプリはUTF-8系の文字コードでしか書き戻せないため、開いてU+FFFD(文字化け)として表示すると、保存時にその文字化けを原本へ上書きして復元不能に破壊してしまう。開かないことで原本を無傷に保つ判断。
- **保存はアトミック**: 同一フォルダ内の一時ファイルへ書き切ってから`File.Replace`(非対応のファイルシステムでは`File.Move(overwrite: true)`にフォールバック)で差し替える。ディスク満杯・ネットワークドライブ切断・書き込み途中のクラッシュがあっても、原本が0バイトや中途半端な内容になることはない。一時ファイルは成否にかかわらず後始末する。
- 保存・読み込みの失敗はエラー通知(4.12参照)で提示する。保存に失敗した場合、未保存フラグ(タイトルの`*`)は落とさない。
- ファイルの読み込み・保存自体に排他制御はない。

### 4.6 最近使ったフォルダ

- ファイルを開く/保存するたびに、そのファイルの親フォルダを最近使ったフォルダの先頭に記録する(既存の同一フォルダは重複除去、最大3件、設定に永続化)。
- 「ファイル」メニューの履歴項目をクリックすると、**そのフォルダを表示した状態でOS標準のファイル選択画面が開く**(`Microsoft.Windows.Storage.Pickers.FileOpenPicker`の`SuggestedFolder`。「開く」と同じ画面・同じフィルタで、直前にユーザーが選んだ場所に上書きされない)。選んだファイルの親フォルダが履歴の先頭に来るため、履歴の並び替えは通常のファイル操作と同じ経路で行われる。専用のファイル一覧ダイアログは持たない。
- ピッカーは存在しないフォルダを渡されてもエラーにせず、黙って「直前に選んだフォルダ」を開く(ユーザーにはクリックしたフォルダが無視されたようにしか見えない)。そのため**ピッカーを出す前に**フォルダを実際に列挙できるか確認し、失敗した場合は原因ごとに区別してエラー通知(4.12参照)を出す。
  - フォルダが存在しない(`DirectoryNotFoundException`): 「このフォルダは見つかりません: {パス}(最近使ったフォルダから削除しました)」を通知し、**履歴から取り除く**。壊れた項目がメニューに残り続けるのを避けるため。削除を行うのはこの場合だけである。
  - アクセス権がない(`UnauthorizedAccessException`)/読み取りに失敗した(`IOException`。ネットワークドライブの切断等)/その他の例外: 原因に応じたメッセージを通知するが、**履歴からは取り除かない**。いずれも一時的な事象である公算が大きく、復旧後の入口を消してしまわないため。「見つからない」と同一視すると、実際には元の場所にあり続けているフォルダを探しに行かせることになる。
  - この確認は、切断されたネットワークドライブや名前解決できないUNCホストでSMB/DNSのタイムアウト(数十秒)ぶんブロックしうるため、バックグラウンドスレッドで実行する(UIは固まらない)。
- 未保存の変更の破棄確認(4.11)は、上記のフォルダ確認の**後**、ファイル選択画面の**前**に行う。存在しないフォルダをクリックしただけで保存を促されることがないようにするため(その経路は現在の文書を差し替えないので確認自体が不要)。

### 4.7 検索・置換

- 独立したダイアログ(`SearchDialog`)としてモーダル表示。エディタの`TextBox`を直接操作する(ViewModelを介さない)。
- オプション: 「大文字と小文字を区別する」「単語単位で検索する」(チェックボックス、既定オフ)。
- 操作: 「前を検索」「次を検索」(検索欄でEnterでも次を検索)、「置換」(現在の選択が検索語と一致する場合のみそれを置換してから次を検索)、「すべて置換」(全件を末尾から置換し、件数をステータス表示)。
- 検索でヒットしない場合・検索語未入力の場合は、ダイアログ内にステータスメッセージを表示する(メイン画面の`InfoBar`はダイアログの背面に隠れて読めないため、このダイアログは自身のステータス欄を持つ)。
- ダイアログ表示中は検索欄に常にフォーカスがある(エディタへは意図的にフォーカスを戻さない)。

### 4.8 設定ダイアログ

保存すると即座に反映される(アプリ再起動不要)。「保存」で確定、「キャンセル」で破棄。項目:

- **テーマ**: システムの既定 / ライト / ダーク(`ComboBox`)。保存時、ウィンドウのルート要素の`RequestedTheme`を即座に切り替える。
- **エディタのフォント**: システムにインストール済みの全フォントファミリーから選択可能(`IsEditable`な`ComboBox`、自由入力も可)。フォントサイズは8〜48の範囲(`NumberBox`)。範囲外の値は保存時にクランプし、欄を空にするなどして数値でなくなった場合は**その設定の変更前の値**へ戻す(エディタ欄はエディタの、プレビュー欄はプレビューの変更前の値)。
- **プレビューのフォント**: エディタと同様にフォントファミリー・サイズ(8〜48)を指定可能。
- **プレビュー背景色**: 「背景色をカスタマイズする」チェックボックスがオフの場合は現在のテーマの既定背景。オンの場合はWindows従来の色選択ダイアログ(`ChooseColorW`、基本色+16件のカスタムカラーパレット)で選んだ色を`!important`でプレビューの`body`背景に強制適用する。カスタムカラーパレットは設定ダイアログの保存/キャンセルに関わらず、色選択ダイアログを閉じた時点で即座にアプリ設定へ永続化される(ネイティブ色選択ダイアログ自体の挙動に合わせた設計)。
- **表(テーブル)のスタイル**: 「ヘッダー行をグレー背景にする」「データ行を1行おきにグレー背景にする(縞模様)」の2つの独立したチェックボックス。両方オンの場合、縞模様はヘッダー行と色が重ならないよう偶数行から開始する。

フォントサイズの上下限(8〜48)はこのダイアログの`NumberBox`も含めて`Models/SettingsLimits.cs`だけに書かれており、`Minimum`/`Maximum`は`x:Bind`でそこを読む(上下限を複数箇所に書いた結果、空欄時のフォールバック値がファイルごとに食い違っていた不具合の再発防止。設定を1箇所にだけ定義する方針については5章参照)。

各フォントピッカー(`IsEditable`な`ComboBox`)は、WinUI3の既知の不具合([microsoft-ui-xaml#7103](https://github.com/microsoft/microsoft-ui-xaml/issues/7103))を避けるため、ダイアログ表示直後にプレースホルダーではなく実際の値が見えるよう内部でフォーカスの当て直しを行っている。

### 4.9 ファイルの関連付け(.mdダブルクリック起動)

- MSIXパッケージが`.md`拡張子をこのアプリに関連付ける(`Package.appxmanifest`の`windows.fileTypeAssociation`、拡張子`.md`のみ。`.markdown`/`.txt`は関連付け対象外 — 開く操作・最近使ったフォルダ機能では扱えるが、エクスプローラーでのダブルクリック起動は`.md`のみ)。
- エクスプローラーで`.md`ファイルをダブルクリックすると、そのファイルを開いた状態でアプリが起動する。起動時に該当ファイルが読み込めない場合(削除済み・権限エラー等)は、既定のサンプル文書にフォールバックしたうえでエラー通知(4.12参照)を出す。
- 起動中のインスタンスへの多重起動時の統合(同一ファイルを開いている既存ウィンドウへのフォーカス移動等)は行わない(1回の起動ごとに新しいプロセス/ウィンドウ)。

### 4.10 ウィンドウタイトル

タイトルバーには「ファイル名」または未保存の変更がある場合「ファイル名 *」を表示する。ファイル名は新規作成時「無題.md」、ファイルを開く/保存すると実際のファイル名に切り替わる。

### 4.11 未保存の変更の破棄確認

未保存の変更(タイトルの`*`)がある状態で現在の文書を差し替える/アプリを閉じる操作を行うと、「保存する / 保存しない / キャンセル」の3択ダイアログを経由する。対象経路は**新規**・**開く**・**最近使ったフォルダから開く**・**ファイル関連付け起動**・**終了メニュー**・**ウィンドウの×ボタン**の全て。

- 「保存する」を選び、保存が失敗した/保存先の選択がキャンセルされた場合は、破棄も終了も行わない(未保存フラグが残っている限り安全側に倒す)。
- 確認ダイアログ自体を表示できなかった場合も破棄しない。ただしウィンドウを閉じる経路だけは逆に閉じる側へ倒す(閉じられないウィンドウを避けるため)。

### 4.12 エラー通知

メイン画面のメニューバー直下に`InfoBar`(`Severity="Error"`)を1つ持ち、ユーザーが知る必要のある失敗をここに表示する(ユーザーが閉じるまで残る)。表示するのは、ファイルの読み込み/保存の失敗、非対応の文字コード、最近使ったフォルダを開けなかった場合、**設定の保存失敗**、WebView2の初期化失敗、プレビュー更新の失敗、設定ダイアログの表示失敗など。

例外は種類を問わず必ず`Services/AppLog.cs`(`Trace`出力)へ記録する。記録と通知は別で、安全に縮退し利用者の対処も不要な失敗(設定の**読み込み**失敗、プレビューのズーム同期失敗、フォント列挙失敗、検索ダイアログの再入など)は記録のみ行う。逆に、外部リソースへのアクセスを`catch`しないこと自体が欠陥として扱われる(通知先がない場面では既定値や`false`へ縮退させて記録する。5章参照)。検索・置換ダイアログは自身のステータス欄を持ち、`InfoBar`はダイアログの背面に隠れるため、そちらの失敗はダイアログ内に表示する。

## 5. データモデルと永続化

`AppSettings`(`Models/AppSettings.cs`)が永続化される設定一式を保持し、`ApplicationData.Current.LocalSettings.Values`(パッケージ化アプリのユーザーごとローカル設定ストア)に保存される(`Services/SettingsService.cs`)。

- **現在の設定の持ち主は`ISettingsService.Current`ひとつだけ**。インターフェースは意図的に`Load()`を公開していない(以前は`MainPage`と`MainWindow`がそれぞれサービスを作って別々に読み込み、後から`Save`した側がもう一方の編集を消していた)。プロセス唯一のインスタンスは`App.Settings`。
- `AppSettings`は**不変の`record`**で、部分更新は`Current with { 変更する項目だけ }`と書く。名前を挙げなかった項目はコンパイラが引き継ぐため、新しいインスタンスを組み立てて他の項目を消してしまう事故(カスタムカラーと最近使ったフォルダで実際に起きた)が起こらない。
- **読み書きのどちらも例外を投げない**。読み込み失敗は既定値へ縮退して`AppLog`に記録するだけ(最初の読み込みは`MainWindow`のコンストラクタで走り、通知先の`InfoBar`はまだ存在しないため)。書き込み失敗は`Save`が`false`を返し、`MainPageViewModel.PersistSettings`だけがそれを「設定を保存できませんでした。この変更は次回の起動時には元に戻ります。」という通知に変える。`Save`は書き込みの前に`Current`を差し替えるので、書き込みに失敗しても画面の見た目と`Current`は一致したままになる。
- 設定の取りうる範囲(フォントサイズの上下限、カスタムカラー数、最近使ったフォルダの件数)は`Models/SettingsLimits.cs`にのみ定義され、サービス・ViewModel・XAMLはそこを参照する。

| 設定項目 | 型 | 既定値 | 備考 |
|---|---|---|---|
| `Theme` | `ElementTheme` | `Default`(システムの既定) | intとして保存 |
| `EditorFontFamily` | `string` | `"Cascadia Mono, Consolas"` | |
| `EditorFontSize` | `double` | `14` | 保存/読込時に8〜48へクランプ |
| `PreviewFontFamily` | `string` | `"Segoe UI, sans-serif"` | |
| `PreviewFontSize` | `double` | `15` | 保存/読込時に8〜48へクランプ |
| `PreviewBackgroundColor` | `string?`(16進カラー) | `null`(テーマ既定) | 読み込み時に`Services/HexColor.cs`の書式検証を通す(このストアはアプリ外から書き換え可能で、値はCSSへ直接埋め込まれるため) |
| `RecentFolders` | `string[]` | `[]` | 最大3件(`SettingsLimits.RecentFolderCount`)、`'\|'`区切りで1つの文字列として保存(フォルダパスに`\|`は含まれない前提) |
| `CustomColors` | `string[]`(16進カラー) | `[]` | 最大16件(`SettingsLimits.CustomColorCount`)、同様に`'\|'`区切り |
| `TableHeaderGrayBackground` | `bool` | `false` | |
| `TableRowStriping` | `bool` | `false` | |

ズーム倍率(`ZoomPercentage`)は意図的に`AppSettings`に含めない(セッション限定、常に100%起動)。

## 6. アーキテクチャ概要

MVVM(CommunityToolkit.Mvvm)構成。

- `Models/AppSettings.cs` — 永続化される設定一式を持つ不変の`record`(5章)。
- `Models/SettingsLimits.cs` — 設定の上下限・件数上限とフォントサイズのクランプ処理を定義する唯一の場所。`const`ではなく静的プロパティなのは、`SettingsDialog.xaml`が`x:Bind`で同じ値を読むため(`x:Bind`はconstにバインドできない)。
- `Services/SettingsService.cs`(`ISettingsService`) — 現在の設定(`Current`)の持ち主かつ永続化先。読み込みは実装内部の一度きりの初期化で、`Load()`は公開しない。`Save`は失敗しても投げずに`false`を返す(5章)。
- `Services/MarkdownRenderer.cs` — Markdig(`UseAdvancedExtensions()`)でMarkdown→HTML変換し、`AppSettings`から導出したCSS(テーマ・フォント・背景色・表スタイル)を埋め込んだHTMLドキュメントを組み立てる静的クラス。
- `Services/MarkdownFileService.cs`(`IMarkdownFileService`) — ファイルの開く/保存ピッカー、読み書き、文字コード・BOM・改行コードの往復保持とアトミック保存(4.5)。
- `Services/DocumentFormat.cs` — 開いている文書の文字コード・BOM有無・改行コード(`DocumentFormat`)、および読み込み結果(`OpenedDocument`)。読み込みが返した`DocumentFormat`を保存へ渡すことが`IMarkdownFileService`のシグネチャ上必須になっており、「読んだ形式で書き戻す」以外を表現できないようにしている。
- `Services/LineEndings.cs` — 「何を改行と見なすか」の唯一の定義(分割用のセパレータ列と文字列、`Detect`/`Normalize`、`DocumentLineEnding`列挙)。以前はセパレータの列挙がエディタの行操作・フッターの行数計算・保存時の正規化の3箇所に散っていた。
- `Services/HexColor.cs` — 16進カラー文字列の書式検証(`GeneratedRegex`)。永続化された値の読み込み時と、CSSへ埋め込む直前の両方で使う。
- `Services/AppLog.cs` — 例外の記録先(`Trace`出力)。`Debug`ではなく`Trace`なのは、Releaseビルドでも記録を残すため。
- `Services/DiscardConfirmationService.cs`(`IDiscardConfirmationService`) — 未保存の変更の破棄確認ダイアログ(4.11)。
- `Services/SystemFonts.cs` — OSインストール済みフォント名の列挙(`System.Drawing.Text.InstalledFontCollection`)。取得に失敗した場合は空リストにフォールバックする。
- `Services/SystemColorDialog.cs` — Win32 `ChooseColorW`のP/Invokeラッパー(WinUI標準の`ColorPicker`/WinFormsの`ColorDialog`ではなく、Windows従来の「色の設定」ダイアログのUIを再現するために採用)。
- `ViewModels/MainPageViewModel.cs` — メイン画面の状態(編集中テキスト、HTMLプレビュー、ズーム、行数・文字数、ファイル名/未保存フラグ)とコマンド(新規/開く/保存/名前を付けて保存)を保持。設定は自前で持たず`_settingsService.Current`を読み書きし、永続化する経路(設定ダイアログの保存・`UpdateCustomColors`・最近使ったフォルダの記録/削除)はいずれも`Current with { 変更する項目だけ }`を`PersistSettings`へ渡す。`PersistSettings`は`Save`の`false`をユーザーへの通知に変える唯一の場所でもある。
- `ViewModels/SettingsViewModel.cs` — 設定ダイアログ用の編集用コピー。`ToAppSettings(current)`は渡された設定にダイアログの編集内容を重ねて返すため、ダイアログが編集しない項目(`RecentFolders`)は呼び出し側が覚えていなくても引き継がれる。渡すのは「保存」が押された時点の値であること(ダイアログ表示中に開かれるネイティブ色選択ダイアログが、その裏でカスタムカラーを永続化するため)。
- `Views/*.xaml(.cs)` — `ContentDialog`群: `SettingsDialog`、`SearchDialog`。(最近使ったフォルダ専用の一覧ダイアログは、OS標準のファイル選択画面に置き換えたため存在しない — 4.6参照。)
- `App.xaml.cs` — エントリポイント。`Microsoft.Windows.AppLifecycle.AppInstance`経由でファイル関連付け起動を検知し、`App.LaunchFilePath`として公開。プロセス唯一の`ISettingsService`も`App.Settings`として公開する(`Frame.Navigate(typeof(MainPage))`は引数なしコンストラクタを要求するため、`MainPage`へはコンストラクタ注入できない)。
- `MainWindow.xaml(.cs)` — アプリ唯一のウィンドウ。`Frame`を`MainPage`へ1度だけナビゲートし、`MainPageViewModel.DisplayTitle`の変更をタイトルバーへ反映する。

テストプロジェクトはなく(WinUI3 UIは意味のある単体テストが困難なため)、変更の検証は`dotnet build -c Debug`が0エラーで通ることと、実機での手動QAのみ。

## 8. 既知の制約・プラットフォーム固有の注意点

- WinUI3のXAML `WebView2`コントロールは`CoreWebView2Controller`を公開していないため、ブラウザネイティブの`ZoomFactor`は利用不可(未解決の既知の制限、[microsoft/microsoft-ui-xaml#5772](https://github.com/microsoft/microsoft-ui-xaml/issues/5772)、[MicrosoftEdge/WebView2Feedback#2538](https://github.com/MicrosoftEdge/WebView2Feedback/issues/2538))。プレビューのズームはCSSインジェクション(`document.body.style.zoom`)による代替実装であり、ネイティブズームに比べてズーム変更時のスクロール位置保持精度が劣る。
- 複数行`TextBox`(`AcceptsReturn="True"`)はユーザー入力の改行を`\r`のみで保持する(`\n`でも`\r\n`でもない)。行数計算・エディタ側の行操作・保存時の改行の書き戻しは、いずれも`\r\n`・`\r`・`\n`すべてに対応させる必要がある(`Services/LineEndings.cs`に一度だけ定義してある。分割時は`\r\n`を`\r`より先に並べないと、CRLFが2つの改行と見なされて空行が生える)。
- `IsEditable`な`ComboBox`にバインドした`Text`は、初回表示時にフォーカスを受け取るまでプレースホルダーが表示され続ける既知の不具合がある([microsoft-ui-xaml#7103](https://github.com/microsoft/microsoft-ui-xaml/issues/7103))。
- `TextBox.SelectionHighlightColorWhenNotFocused`は既定で透明なため、フォーカスが外れると選択範囲が見えなくなる(本アプリのエディタでは明示的に`ThemeResource`を設定して回避済み)。
- `KeyboardAccelerator`の修飾キー一致は完全一致(スーパーセット一致ではない)。メインキーの"+"のように、一部キーボード配列でShiftを要するキーは、Shiftあり/なし両方の修飾キーの組み合わせで登録する必要がある。
- `KeyboardAccelerators`を持つ要素は、既定(`KeyboardAcceleratorPlacementMode="Auto"`)でそのショートカットのツールチップを表示する。本アプリはズームのアクセラレータを`Page`自身に登録しているため、その所有者はコンテンツ領域全体になり、ポインタがウィンドウに入った瞬間にツールチップが出てエディタ・プレビュー上を追従した(しかも生のOEMキー名から「CTRL++」と表示される)。`MainPage`のルート`Page`に`KeyboardAcceleratorPlacementMode="Hidden"`を指定して抑止している。メニューの`MenuFlyoutItem`が項目内に描くショートカット表記は別の仕組みなので影響を受けない。
- プレビュー領域(WebView2)はネイティブHWNDとして描画されるため、その領域上でのポインタ操作(Ctrl+マウスホイール等)はXAML側のポインタイベントを経由しない。そのためプレビュー上でのズーム操作をXAML側で横取りすることはできず、WebView2自身のネイティブズームを無効化することで対処している。
- ズーム倍率はアプリケーション再起動のたびに100%へリセットされる(意図的な仕様、5章参照)。
- 想定外の例外は握りつぶさず、必ず`AppLog`へ記録したうえで、利用者の対処が要るものはメイン画面の`InfoBar`へ通知する(4.12)。捕捉自体をやめてクラッシュさせることはしない(未保存内容の消失を防ぐため)。外部リソースへのアクセスを一切捕捉しないのも同じ欠陥として扱う — `SettingsService`がリポジトリ内で唯一そうなっており、`LocalSettings`の読み込み失敗が、通知先のUIがまだ存在しない`MainWindow`のコンストラクタでアプリごと落としていた。
- `CoreWebView2.NavigateToString`には文字列長の上限(約2MB)があり、超えると例外を投げる。プレビュー更新は`MarkdownText`のsetterから`PropertyChanged`経由で同期的に呼ばれるため、ここで例外を漏らすとXAMLのバインディング更新を巻き込んでプロセスごと落ちる。更新経路は1メソッド(`MainPage.UpdatePreview`)に集約し、必ず捕捉する。
- `Control.PreviewKeyDown`(エディタの`TextBox`で使用)は既定のキー処理より前に発火し、ハンドラ内で`e.Handled = true`にすることで既定のEnter処理(改行挿入)をキャンセルできる(リスト自動継続機能で利用)。日本語IMEの変換確定Enterはこのハンドラに捕捉されず、通常通り動作する。

## 9. 対象外(未実装)の機能

- カーソル位置(行・列)のフッター表示
- 選択範囲のみの文字数表示
- ズーム倍率のアプリ再起動後の保持
- プレビュー(WebView2)上での直接のCtrl+マウスホイールズーム操作
- 複数ウィンドウ・複数タブでの同時編集
- `.markdown`/`.txt`拡張子のOSファイル関連付け(エクスプローラーからのダブルクリック起動)
- Markdown内の生HTMLのサニタイズ(実行はCSPと`IsScriptEnabled=false`で封じているが、HTML自体の除去・許可タグのホワイトリスト化は行わない)
- Shift-JISなどUTF-8系以外の文字コードの読み書き(開けずにエラー通知する。対応するには`System.Text.Encoding.CodePages`の導入と、そのコードページで表現できない文字を保存時にどう扱うかの決定が必要)
- 改行コードが混在したファイルの原形保持(最初に現れた改行コードに全体を揃えて保存する。4.5参照)
- 文字コード・改行コードのUI上での表示や切り替え(フッターにも設定にも出さず、開いたときの形をそのまま保つのみ)
- 自動保存・バックアップ・変更履歴
- Markdown記法ツールバーの記法トグルオフ(同じボタンの再クリックで記法を除去する)
- ツールバーのウィンドウ最小幅対応・折り返し/オーバーフロー処理
- 引用(`> `)のEnterキーによる自動継続
- 箇条書き・番号付きリスト・引用相互の記法の置き換え(見出し間の切り替えのみ対応)
- ネストされたリストのEnterキーによる自動継続
