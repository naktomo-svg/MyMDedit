# バックログ

機能追加の候補です。まだ設計も着手もしていません。手間は小・中・大の目安で、着手するときに見積もり直します。

「セキュリティ再点検」は、`CLAUDE.md`の「Security re-audit triggers」に当たるものです。着手したら、少なくとも`tests/security/tools/run-all.ps1`・`cargo deny check`・変更したモジュールのファズテストを実行し、結果をコミットメッセージかPRの説明に書きます。

記録日: 2026-10-30(6〜8と「余裕があれば」の一部は 2026-11-02 に追記。GitHub の Markdown エディタ(Issue・PR のコメント欄)と GitHub Docs の記述を比べて、取り入れる価値があるものを選びました)

9〜12と「余裕があれば」の後半も 2026-11-02 の追記です。GitHub で公開されている Markdown エディタの README と機能ページを読み、複数のエディタが備えているもの、または MyMDedit の作り(プレーンテキストのエディタ + 横に並べたプレビュー)に無理なく載るものを選びました。読んだのは次の8つです。

- MarkText(marktext/marktext)
- Markdown Monster(RickStrahl/MarkdownMonster)
- ghostwriter(KDE/ghostwriter)
- Markdown Edit(mike-ward/Markdown-Edit)
- Markdown All in One(yzhang-gh/vscode-markdown)
- Zettlr(Zettlr/Zettlr)
- VNote(vnotex/vnote)
- EasyMDE(Ionaru/easy-markdown-editor)

フォーカスモード、タイプライターモード、現在行の強調、スペルチェック、スニペット、スライド表示は、RichEdit では作りにくいか、使う場面が少ないため見送りました。

## 進める順番の案

1と2を一緒に入れ、次に4に時間をかけて取り組みます。6と7はどちらも小さく、エディタの操作だけで完結するので、1・2と同じ時期に入れられます。

## 候補

### 1. ファイルのドラッグ＆ドロップで開く

- **手間**: 小
- **理由**: 今は「開く」ダイアログとコマンドライン引数でしかファイルを開けません。エクスプローラーから`.md`をドロップできると、毎日の使い勝手が一番変わります
- **方針**: `DragAcceptFiles`と`WM_DROPFILES`で受け取り、今の「開く」と同じ処理（未保存の確認、文字コードの判定、`read_at_most`）に渡します。複数のファイルが落とされたときは、最初の1つだけを開きます
- **注意**: プレビュー（WebView2）の上に落とされた場合の扱いを決める必要があります。WebView2は、ドロップされたファイルへ自分で移動しようとします
- **セキュリティ再点検**: 要（ファイルが入る新しい経路）

### 2. ウィンドウの位置・大きさ・左右の分割比率を覚える

- **手間**: 小
- **理由**: 起動するたびにウィンドウの配置を直す手間がなくなります
- **方針**: `settings.json`に項目を追加し、上下限は`settings::limits`に置きます。保存は`SettingsStore::update`を通します。保存した位置が今の画面の外になっていたら（モニターを外したときなど）、既定の位置に戻します
- **セキュリティ再点検**: 不要

### 3. HTMLで書き出す

- **手間**: 小〜中
- **理由**: 社内での共有やブログへの貼り付けに使えます。プレビュー用のHTMLはすでに作っています
- **方針**: `render.rs`が作るHTMLを、`document.rs`と同じ方法（一時ファイルに書いてから差し替える）で保存します
- **決めること**: CSPを残すかどうか。残せば安全ですが、書き出したファイルをほかのツールで加工しにくくなります。コピーボタンの要素を外すかどうか
- **セキュリティ再点検**: 不要（プレビューには手を入れない）。ただし、書き出したHTMLの中にCSPがあるかどうかはテストで確かめます

### 4. 文書のそばにあるローカル画像をプレビューに出す

- **手間**: 中
- **理由**: 今のCSPは`img-src data: https:`なので、`![](./img/a.png)`のような相対パスの画像は表示されません。Markdownでメモを書くときに一番困るところです
- **方針**: 文書と同じフォルダ（とその下）の画像だけを、アプリ側で読み込んで`data:`のURIに変えて埋め込みます。CSPは今のままにします
- **やってはいけない方法**: `file:`を許可すること。`SetVirtualHostNameToFolderMapping`でフォルダを丸ごと公開すること
- **注意**: `..`・絶対パス・UNCパス（`\\server\share`。開くだけで認証情報が送られる）・シンボリックリンクで、文書のフォルダの外に出ないようにします。読み込むのはディスク上のファイルだけで、大きさにも上限を設けます。プレビューを作り直すたびに読み込み直さないよう、キャッシュも要ります
- **セキュリティ再点検**: 要（`render.rs`のCSPとHTMLの生成に手を入れ、パスが入る新しい経路も増える）。UNCパスへの通信が起きないことを確かめるペイロードを`tests/security/`に足します（`unc-leak.md`が参考になります）

### 5. 最近使ったファイルの一覧

- **手間**: 小
- **理由**: 今あるのは、最近使ったフォルダの3件だけです。同じ文書を開き直すことが多いので、ファイル単位の一覧のほうが早く開けます
- **方針**: 今ある「最近使ったフォルダ」と同じ仕組み（`settings.rs`の件数の上限、メニューの`ID_RECENT_BASE`の範囲）でファイルの一覧を作ります。存在しなくなったファイルは、選ばれたときにエラーを出して一覧から外します
- **セキュリティ再点検**: 不要

### 6. 記法のキーボードショートカット

- **手間**: 小
- **理由**: 今は太字やリンクをツールバーのボタンでしか入れられず、手をキーボードから離す必要があります。GitHub のコメント欄と同じキーにすれば、覚え直さずに使えます
- **方針**: GitHub と同じ割り当てを`app::ACCELERATORS`に足し、今のツールバーと同じコマンドを呼びます（1回の元に戻すで戻せる点も同じ）
  - Ctrl+B 太字、Ctrl+I 斜体、Ctrl+E インラインコード、Ctrl+K リンク
  - Ctrl+Shift+8 箇条書き、Ctrl+Shift+7 番号付き、Ctrl+Shift+. 引用
- **注意**: RichEdit は Ctrl+E（中央ぞろえ）などに自前の動作を持っています。アクセラレータが先に取るので実害はないはずですが、実機で確かめます。日本語配列でも、Shift+7 などの仮想キーは同じ`'7'`です。プレビューにフォーカスがあるときは`AcceleratorKeyPressed`から転送されてくるので、エディタに書き込んでよいかを決めます。メニューの表記と、仕様書7章のショートカット一覧は`ACCELERATORS`から作られます
- **セキュリティ再点検**: 不要

### 7. 文字列を選んで URL を貼り付けるとリンクにする

- **手間**: 小
- **理由**: GitHub では、文字列を選んだまま URL を貼り付けると`[選んだ文字列](URL)`になります。今はリンクのボタンを押してから URL を貼る2手間で、選んだ文字列は URL で上書きされてしまいます
- **方針**: エディタのサブクラスで Ctrl+V・Shift+Insert・`WM_PASTE`を受け、次の条件がそろったときだけリンクにします。それ以外は今までどおり貼り付けます
  - 選択範囲が1行の中にある
  - クリップボードの文字列が、空白や改行を含まない`http:`/`https:`/`mailto:`の URL 1つだけ
  - 書き換えは`md_ops`の純粋関数（`Edit`を返す）にして、ラベルのエスケープはリンクのボタンと同じ処理を使います。1回の元に戻すで、ただの貼り付けの結果に戻らず、貼り付ける前に戻ります
- **決めること**: リンクにせずそのまま貼りたいときの逃げ道。GitHub は Ctrl+Shift+V を「プレーンテキストとして貼り付け」にしています
- **セキュリティ再点検**: 不要（クリップボードから読むのは、今の貼り付けと同じ`CF_UNICODETEXT`だけ）

### 8. GitHub のアラート（`> [!NOTE]`など）をプレビューに出す

- **手間**: 小
- **理由**: README などで GitHub のアラートを使っていると、今のプレビューでは`[!NOTE]`という文字の入った、ただの引用として出ます。GitHub 上の見た目と違うので、仕上がりを確かめられません
- **方針**: comrak 0.56 の`extension.alerts`を有効にし、5種類（NOTE・TIP・IMPORTANT・WARNING・CAUTION）の色付きの枠を、`render.rs`の CSS にライトとダークの両方の配色で足します。スクリプトは要りません
- **注意**: 仕様書 4.2 の拡張の一覧を更新します。見出しの文言（「Note」など）を日本語にするかどうかを決めます
- **セキュリティ再点検**: 不要（CSP とプレビューのハンドラーには手を入れない）。ただし出力する HTML が変わるので、`render_markdown`の fuzz は回します

### 9. 表の整形（列をそろえる）

- **手間**: 小〜中
- **理由**: 表を手で書き足すと、`|`の位置がずれて読みにくくなります。Markdown All in One・Markdown Monster・VNote がそろって持っている機能です
- **方針**: キャレットのある表（またはその選択範囲の表）の各セルの前後の空白を整え、列ごとに幅をそろえて書き直します。区切り行の`:---:`などの寄せの指定は残します。`md_ops`の純粋関数（`Edit`を返す）にするので、1回の元に戻すで戻せます。編集メニューとツールバーの「その他」から呼びます
- **注意**: 日本語の全角文字は半角2文字分の幅として数えます（東アジアの文字幅の判定に`unicode-width`クレートを使うなら、依存が増えるので`cargo deny check`と THIRD-PARTY-NOTICES.txt の作り直しが要ります）。それでもエディタのフォントによっては完全にはそろいません。セルの中の`\|`はセルの区切りとみなしません。コードブロックの中の行には手を付けません
- **セキュリティ再点検**: 不要

### 10. 番号付きリストの番号を振り直す

- **手間**: 小
- **理由**: 途中に項目を足したり消したりすると、番号が飛んだり重なったりします。Markdown All in One は自動で、EasyMDE などはコマンドで直せます。仕様書9章でも未実装として挙げています
- **方針**: キャレットのある番号付きリスト（同じ字下げで続く`N. `の行）を、先頭の番号から1ずつ振り直す`md_ops`の純粋関数を作り、コマンドとして呼びます。Enter で項目を足したとき（4.8の自動継続）に、続く行も振り直すかどうかは別に決めます
- **セキュリティ再点検**: 不要

### 11. 目次を挿入する

- **手間**: 小〜中
- **理由**: README や長いメモの先頭に、見出しへのリンクの一覧を置きたい場面は多いです。Markdown All in One と Markdown Monster が持っています
- **方針**: 「見出しへ移動」と同じ見出しの抽出（`md_ops::headings`）から、`- [見出し](#id)`の入れ子のリストを作ってキャレット位置に挿入します。id はプレビューと同じ comrak の規則（`Anchorizer`）で作り、重複したときの`-1`・`-2`も合わせます
- **決めること**: 挿入した目次をあとで更新できるようにするか（Markdown All in One は目次を目印で囲み、保存のたびに書き直します）。最初は「挿入するだけ」にして、更新はもう一度挿入し直してもらう形が簡単です
- **セキュリティ再点検**: 不要

### 12. 自動バックアップと、異常終了したあとの復元

- **手間**: 中
- **理由**: 今は保存していない編集が、停電や強制終了、アプリの異常終了でそのまま消えます。Markdown Monster・ghostwriter・Markdown Edit・EasyMDE がそろって自動保存かバックアップを持っています。技術負債レポートで意図的な設計として見送ったB2-1（確認ダイアログを出せないと内容を捨てる）とB2-10（Windowsの終了時の扱い）も、この仕組みがあれば安全側に寄せられます
- **方針**: 元のファイルは上書きせず、未保存の内容だけを一定の間隔で`%LOCALAPPDATA%\MyMDedit\recovery\`へ書きます（文書と同じアトミック保存）。保存したとき、または保存せずに閉じることを選んだときに消します。次の起動時に残っていたら、復元するかを尋ねます
- **注意**: 復元用のファイルには文書の中身がそのまま入ります。置き場所はユーザーのローカルだけにし、復元しないと選ばれたら消します。複数のインスタンスが同時に動いても、互いのファイルを取り違えないようにします。読み込みは`read_at_most`を通します
- **セキュリティ再点検**: 要（ファイルが入る新しい経路）
